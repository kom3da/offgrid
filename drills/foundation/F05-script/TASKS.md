## ねらい

手で打っていたコマンドの並びを、失敗したらきちんと止まるスクリプトにできるようになる。閉域のサーバーには、Goのコンパイラも便利な自動化の道具もないことが多いが、`bash` は必ずある。バックアップや定期的な確認を、その場で安全に自動化できる力は、どの現場でもそのまま使える。

## このユニットで身につけること

- スクリプトのファイルを作り、実行できるようにして動かす
- 変数と引数を、空白を含む値でも壊れないように扱う
- `if` でファイルの有無や値を調べ、場合に応じて処理を分ける
- `for` と `while read` で、複数のファイルや行を順に処理する
- エラーメッセージを標準エラーに出し、終了コードで失敗を伝える
- `set -euo pipefail` で、失敗に気づかず進むスクリプトを防ぐ
- `shellcheck` の指摘を読み、自分で直す

## キーワード

分からない語は、まず `man bash` の中を検索するか、`help コマンド名`（`help test`、`help set` など）で調べる。

- **シバン（shebang）**：スクリプトの1行目の `#!` で始まる行。どのプログラムで実行するかを指定する
- **変数展開**：`$name` や `"$name"` が、変数の値に置き換わること
- **クォート**：`'` や `"` で囲むこと。空白や記号を、シェルに解釈させずにそのまま渡す
- **位置パラメータ**：スクリプトに渡された引数。`$1`、`$2`、`$#`、`"$@"` で受け取る
- **コマンド置換**：`$(コマンド)` と書くと、そのコマンドの出力に置き換わる
- **`test`（`[ ]`）**：条件を調べて、結果を終了コードで返すコマンド。`if` と組み合わせる
- **終了コード**：コマンドやスクリプトが終わるときに返す数。0が成功（F4）
- **`shellcheck`**：シェルスクリプトの間違いやすい書き方を、指摘してくれる道具

## 課題

小さなスクリプトを1つずつ書く。書くたびに `shellcheck ファイル名` にかけ、指摘をすべて読む。

1. `hello.sh`：1行目の `#!/usr/bin/env bash` は何のためにあるか。`./hello.sh` と `bash hello.sh` の違いは何か（F2の課題を思い出す）
2. `var.sh`：変数に値を入れて表示する。`name=value` の `=` の前後に空白を入れると、どうなるか。なぜか。`$name` のすぐ後ろに文字を続けたいとき（例：値に `_backup` を付ける）は、どう書くか
3. `quote.sh`：空白を含むファイル名（`my file.txt`）を変数に入れ、`ls -l $f` と `ls -l "$f"` の違いを確かめる。`'` と `"` の違いも確かめる。`shellcheck` は、このスクリプトに何と言うか
4. `args.sh`：引数の数（`$#`）と、すべての引数（`"$@"`）を1行ずつ表示する。引数が1つもなければ、使い方を標準エラーに出して、終了コード1で終わる。`./args.sh 'a b' c` を渡したとき、`"$@"` と `$@` で、表示される行数はどう違うか
5. `check.sh`：引数で受けたパスが、ファイルか、ディレクトリか、存在しないかを表示する（`[ -f ]`、`[ -d ]`）。数の比較（`-eq`、`-gt`）と文字列の比較（`=`、`-z`）も試す。`[` と `]` の内側の空白を消すと、どうなるか
6. `loop.sh`：カレントディレクトリの `*.txt` を1つずつ処理する `for`。`{1..5}` の連番。`while read -r line` で、ファイルを1行ずつ読む。`*.txt` に当てはまるファイルが1つもないとき、`for` は何回まわり、変数には何が入るか
7. `func.sh`：メッセージを標準エラーに出して終了する関数 `die` を作り、使う。関数の中の `$1` は、スクリプトの `$1` と同じものか。`./func.sh; echo $?` で、終了コードを確かめる
8. `strict.sh`：`set -euo pipefail` の3つを1つずつ外し、次の場面で動きがどう変わるかを確かめて、表にする
   - 定義していない変数を使った
   - 途中のコマンドが失敗した
   - パイプの途中のコマンドが失敗した
9. `stamp.sh`：`man date` で、今の日付と時刻を `20260917-093000` のような形で出す書式を探す。その出力を、コマンド置換で変数に入れて表示する。ディレクトリのパスから、最後の名前の部分だけを取り出すコマンドも探す（`data/` のように、末尾に `/` が付いていても動くこと）
10. **本題** `backup.sh`：引数で受けたディレクトリを、`backup/<ディレクトリ名>-<日付と時刻>` にコピーする。`~/sandbox/f05` に移動してから、スクリプトをパスで指定して呼ぶ（バックアップが `~/sandbox/f05/backup/` にできる）。次の場合にも、正しく動くこと
    - 引数がない → 使い方を出して終了コード1
    - ディレクトリが存在しない → エラーを標準エラーに出して終了コード1
    - ディレクトリ名に空白が含まれる
11. 応用：`backup.sh` に、7日より古いバックアップを消す機能を足す（`find -mtime`）。実際には消さずに、消す対象だけを表示するオプションも付ける。試すための「古いバックアップ」は、`man touch` で更新日時を過去に変えるオプションを探して作る

### 発展（任意）

- F3の本題（アクセス数上位のIPアドレス）の1行を `top.sh` にする。ログのファイル名と、表示する件数を、引数で受ける

## 詰まりやすいところ

- `./xxx.sh` で `Permission denied` → F2の課題を思い出し、`ls -l` で確かめる
- `bad interpreter` と出る、または行末に `^M` や `\r` が見える → `xxd` で行末のバイトを見る（F1）。エディタが行末をどう扱っているかを確かめる（`file` コマンドでも分かる）
- `[: missing ]` や `[-f: command not found` → `type [` を実行し、`[` が何者かを確かめる
- `set -e` を書いたのに、失敗しても止まらない場面がある → `help set` の `-e` の説明で、例外にあたる場面を探す
- 空白を含むディレクトリで、`cp` が「そんなファイルはない」と言う → `shellcheck` の指摘と、`quote.sh` の結果を見直す
- 日付がそのままの文字（`$(date ...)`）で出る、または空になる → 囲んでいるクォートの種類を確かめる

## 完了条件の確かめ方

- `backup.sh` に対する `shellcheck` の指摘がゼロ
- 課題10の3つの場合と、ふつうに成功する場合を実際に試し、結果と終了コード（`echo $?`）を `notes.md` に貼ってある
- コピーされたバックアップの中身が、元と同じであることを確かめてある（F2、F3で使ったコマンドで比べる）
