## ねらい

「動いているプログラム（プロセス）」を見つけ、止め、その入出力と環境を操れるようになる。閉域の現場で「サーバーが重い」「プログラムが止まらない」「設定したはずの値が効いていない」と言われたとき、最初に見るのがプロセスと環境変数。再起動に頼らず、何が動いているかを自分で確かめて対処できるようにする。

## このユニットで身につけること

- 動いているプロセスの一覧から、目的のプロセスとそのPID・親プロセスを見つける
- コマンドをバックグラウンドで動かし、フォアグラウンドと行き来させる
- シグナルを送って、プロセスを止める・一時停止する・再開する
- CPUを使いすぎているプロセスを `top` で見つける
- 環境変数を設定し、子プロセスに伝わる場合と伝わらない場合を区別する
- 標準出力と標準エラーを別々の先へ流し、終了コードで成功・失敗を判定する

## キーワード

分からない語は、まず `man コマンド名` か `コマンド名 --help` で調べる。`cd` や `jobs` のようにシェルに組み込まれたコマンドは、`help コマンド名` で調べる。

- **プロセス**：動いている最中のプログラム。同じプログラムから、いくつも作れる
- **PID・PPID**：プロセスごとに付く番号と、そのプロセスを起動した親プロセスの番号
- **フォアグラウンド・バックグラウンド**：端末を占有して動く状態と、裏で動いて次のコマンドを打てる状態
- **ジョブ**：シェルが管理している、自分が起動したコマンドのまとまり
- **シグナル**：プロセスへ送る合図。「終了してほしい」「強制終了」「一時停止」などの種類がある
- **環境変数**：プロセスが持っている「名前＝値」の設定。子プロセスに引き継がれる
- **`PATH`**：コマンドを探すディレクトリの一覧を持つ環境変数
- **標準入力・標準出力・標準エラー**：プロセスが最初から持っている3つの入出力。番号は 0、1、2
- **終了コード**：コマンドが終わるときに返す数。0が成功、0以外が失敗

## 準備

```sh
mkdir -p ~/sandbox/f04
cd ~/sandbox/f04
```

シェルを2つ開いておくと進めやすい（ターミナルをもう1つ開き、同じようにUbuntuに入る）。

## 課題

1. `ps`、`ps aux`、`ps -ef` の出力を見比べる。PID、PPID、STAT の列は何を表すか。`echo $$` で、今のシェルのPIDを確かめる。`ps -ef --forest` で、親子関係を見る
2. シェルの中で `bash` を実行し、もう1つシェルを起動する。その中で `echo $$` と `echo $PPID` を実行し、課題1で確かめたPIDと比べる。`exit` で抜けたあとは、どうなるか。自分のシェルの親は誰か、さらにその親は誰かを、PID 1 までたどる
3. `sleep 300` を実行し、Ctrl+C で止める。もう一度実行して Ctrl+Z を押し、`jobs`、`bg`、`fg` を試す。最初から `sleep 300 &` で起動した場合と比べる。Ctrl+Z のあと、`ps` のSTAT列はどうなっているか
4. `sleep 300 &` を起動し、もう1つのシェルから `ps` で探して `kill` する。`kill -l` で、シグナル（プロセスへの合図）の一覧を見る。SIGTERM、SIGKILL、SIGINT の違いを調べる。`kill -STOP` と `kill -CONT` を試す。Ctrl+C と Ctrl+Z は、それぞれどのシグナルにあたるか
5. PIDの探し方を比べる：`ps aux | grep sleep` と `pgrep -a sleep` の結果は、どう違うか。前者に、探していない行が混ざるのはなぜか
6. `yes > /dev/null &` を実行する。`top` を開き、CPUを使っているプロセスを見つけて止める。`top` の1行目の load average は何を表すか。`yes` を止める前と後で、値はどう変わっていくか
7. 環境変数：`env` の出力から `HOME`、`PATH`、`USER` を探す。`FOO=bar` と `export FOO=bar` のそれぞれのあとで、`bash -c 'echo $FOO'` を実行し、結果の違いを説明する。`FOO=baz bash -c 'echo $FOO'` のように1行で書いた場合、そのあとの `echo $FOO` はどうなるか
8. `PATH` の意味を調べる。`which ls` と `type cd` の結果はなぜ違うか。`PATH` を空にすると `ls` はどうなるか（別のシェルを開き直せば元に戻る）。そのとき `cd` は使えるか。なぜか
9. 標準入力（0）・標準出力（1）・標準エラー（2）：`ls /nonexistent /tmp > out.txt 2> err.txt` を実行し、2つのファイルの中身を確かめる。`2>&1` と `/dev/null` の使い方を試す（F3の復習。ここでは「プロセスが持つ3つの出入口」として見直す）
10. 終了コード：`true; echo $?`、`false; echo $?`、`grep` が見つけたときと見つけなかったときの `$?` を確かめる。`&&` と `||` を使い、「成功したら次を実行」「失敗したらメッセージを出す」を書く。`kill` で止められた `sleep` の終了コードは、いくつになるか
11. `ls /proc/$$` と `head /proc/$$/status` で、自分のシェルの情報をファイルとして見る。`/proc` とは何か。`ls -l /proc/$$/fd` に出る 0、1、2 は、課題9の何にあたるか
12. **本題**：何も見ずに、次を通してやる。長時間動くコマンドをバックグラウンドで起動する → 別のシェルからPIDを探す → 止める → 止まったことを、両方のシェルで確かめる。打ったコマンドと結果を `notes.md` に貼る

### 発展（任意）

- バックグラウンドでコマンドを動かしたままシェルを閉じると、そのプロセスはどうなるか。`exit` で閉じた場合と、ターミナルのウィンドウごと閉じた場合を、別のシェルから確かめる。`nohup` は何のためにあるか
- `man bash` で `trap` を調べ、Ctrl+C を押すとメッセージを出すようにシェルを設定してみる（シェルを開き直せば元に戻る）
- `nice` は何をするコマンドか。`yes > /dev/null` を2つ、片方だけ `nice` 付きで動かし、`top` のどの列が変わるかを見る（CPUが複数ある環境では、差が見えにくい。なぜか）

## 詰まりやすいところ

- Ctrl+Z を押したら、コマンドが終わったように見える → `jobs` と、`ps` のSTAT列を確かめる
- もう1つのシェルで `jobs` を実行しても、何も出ない → `jobs` が「誰の」ジョブを表示するのかを、`help jobs` と `man bash` のジョブ制御の節で調べる
- `kill` したのに、プロセスが残っている → 送ったシグナルの種類と、そのプロセスのSTAT列を確かめる
- `bash -c "echo $FOO"` のように `"` で囲むと、結果が変わる → `$FOO` を値に置き換えているのが、外側と内側のどちらのシェルかを考える
- `kill %1` と `kill 1` の違いが分からない → `%` の意味を、`man bash` のジョブ制御の節で調べる
- `top` や `man` の画面から抜けられない → `q` を押す。`top` の中で `h` を押すと、使い方が出る
