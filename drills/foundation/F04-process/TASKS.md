# F4：プロセスとOS（課題シート）

この `TASKS.md` はカリキュラムの一部なので、書き換えない。コマンドを試す場所は、下の「準備」で作る `~/sandbox/` の中。メモ（`notes.md`）、`explain.md`、自分で書いたスクリプトは、リポジトリの中のこのディレクトリに、AI機能を切ったVS Codeで書く（F6からは `vim` や `nano` でもよい）。

## ねらい

「動いているプログラム（プロセス）」を見つけ、止め、その入出力と環境を操れるようになる。

## 平日に読むもの

『新しいLinuxの教科書』のプロセスとジョブを扱う章。余裕があれば『［試して理解］Linuxのしくみ』のプロセス管理の章。

## 準備

```sh
mkdir -p ~/sandbox/f04 && cd ~/sandbox/f04
```

シェルを2つ開いておくと進めやすい（ターミナルをもう1つ開き、同じようにUbuntuに入る）。

## 課題

1. `ps`、`ps aux`、`ps -ef` の出力を見比べる。PID、PPID、STAT の列は何を表すか。`echo $$` で、今のシェルのPIDを確かめる。`ps -ef --forest` で、親子関係を見る
2. `sleep 300` を実行し、Ctrl+C で止める。もう一度実行して Ctrl+Z を押し、`jobs`、`bg`、`fg` を試す。最初から `sleep 300 &` で起動した場合と比べる
3. `sleep 300 &` を起動し、もう1つのシェルから `ps` で探して `kill` する。`kill -l` で、シグナル（プロセスへの合図）の一覧を見る。SIGTERM、SIGKILL、SIGINT の違いを調べる。`kill -STOP` と `kill -CONT` を試す
4. `yes > /dev/null &` を実行する。`top` を開き、CPUを使っているプロセスを見つけて止める。`top` の1行目の load average は何を表すか
5. 環境変数：`env` の出力から `HOME`、`PATH`、`USER` を探す。`FOO=bar` と `export FOO=bar` のそれぞれのあとで、`bash -c 'echo $FOO'` を実行し、結果の違いを説明する
6. `PATH` の意味を調べる。`which ls` と `type cd` の結果はなぜ違うか。`PATH` を空にすると `ls` はどうなるか（別のシェルを開き直せば元に戻る）
7. 標準入力（0）・標準出力（1）・標準エラー（2）：`ls /nonexistent /tmp > out.txt 2> err.txt` を実行し、2つのファイルの中身を確かめる。`2>&1` と `/dev/null` の使い方を試す
8. 終了コード：`true; echo $?`、`false; echo $?`、`grep` が見つけたときと見つけなかったときの `$?` を確かめる。`&&` と `||` を使い、「成功したら次を実行」「失敗したらメッセージを出す」を書く
9. `ls /proc/$$` と `head /proc/$$/status` で、自分のシェルの情報をファイルとして見る。`/proc` とは何か

## 完了条件の確かめ方

何も見ずに、次の一連の操作ができる：長時間動くコマンドをバックグラウンドで起動する → 別のシェルから探す → 止める → 止まったことを確かめる。
