## ねらい

コンピュータの中では、数も文字もすべて「バイトの並び」であることを、自分の目で確かめる。閉域の現場では、文字化けや壊れたファイルに出会っても、便利な変換ツールを後から入れられない。最初から入っている `xxd` で中身をそのまま見られれば、「何が入っているか」から調べ始められる。

これが最初のユニット。コマンドの細かい意味は、まだ分からなくてよい。課題に書かれたコマンドを1文字ずつ正確に打ち、出てきた結果を観察することに集中する。

## このユニットで身につけること

- `man` でコマンドの説明を開き、読み、閉じる
- 10進数・2進数・16進数を、紙の上で相互に直す
- `xxd` の出力を読み、ファイルや文字列が何バイトで、各バイトの値が何かを言う
- 文字数とバイト数の違いを、`wc` で確かめる
- UTF-8で、1文字が何バイトになるかを、バイトの先頭のビットから読み取る
- 自分の環境のCPU・メモリ・ストレージの量を、コマンドで調べる

## キーワード

分からない語は、まず `man コマンド名` で調べる（`man` は、コマンドの説明書を開くコマンド。矢印キーかスペースで進み、`q` で閉じる）。

- **ビット**：0か1のどちらかを表す、情報の最小の単位
- **バイト**：8ビットをひとまとめにしたもの。ファイルのサイズやメモリの量を数える単位
- **2進数・16進数**：0と1だけ、または0〜9とa〜fの16種類の文字で数を表す書き方
- **文字コード**：文字とバイトの値の対応を決めた約束ごと
- **ASCII**：英数字と記号を、1文字1バイトで表す古くからの文字コード
- **UTF-8**：世界中の文字を、1文字あたり1〜4バイトで表す文字コード。今の標準
- **CPU・メモリ・ストレージ**：計算する部品、作業中のデータを置く部品、データを保存しておく部品
- **16進ダンプ**：ファイルの中身を、1バイトずつ16進数で表示したもの。`xxd` が出す

## 課題

コマンドは、コピーせずに手で打つ。`'`（シングルクォート）と `"`、`|`（縦棒）と `l`（エル）を打ち間違えやすい。日本語と絵文字は、手元のOSの入力方式で入れる（絵文字は Windows なら Win+.、macOS なら Ctrl+Cmd+Space）。打てなければ、その文字だけコピーしてよい。

1. `man xxd` を開く。矢印キーとスペースで読み進め、`q` で閉じる。1行目あたりに書かれている、`xxd` の一言の説明をメモに写す
2. 10進数の 5、10、255、256 を、紙の上で2進数と16進数に直す。そのあと `printf '%x\n' 255` や `echo $((2#1010))`、`echo $((16#ff))` で答え合わせをする（数の部分を変えて使う。この書き方の意味は、今は分からなくてよい）
3. 1バイト（8ビット）で表せる数は、いくつからいくつまでか。それを16進数で書くと、何桁になるか。課題2の結果から考えて、メモに書く
4. `printf 'A' | xxd` を実行する。`|` は、左のコマンドの結果を右のコマンドに渡す記号で、F3で学ぶ。今は、書かれたとおりに打てばよい。出力は左・中央・右の3つの部分に分かれている。それぞれが何を表すかを `man xxd` で調べて、メモに書く
5. `A`、`a`、`0`（数字のゼロ）、空白、改行のバイトの値を `xxd` で調べ、表にする。`echo 'A' | xxd` と `printf 'A' | xxd` の出力は何が違うか。なぜ違うか
6. 課題5の表を見る。`A` と `a` の値の差はいくつか。`B` と `b` ではどうか、予想してから確かめる。数字の `0` と、数の0は、同じバイトの値か
7. **本題**：`printf 'あ' | xxd` を実行する。「あ」は何バイトか。`printf 'aあ😀' | xxd` では、それぞれの文字が何バイトになっているか。`wc -c` と `wc -m` の結果を比べて確かめる（`printf 'aあ😀' | wc -c` のように、`xxd` の部分を入れ替える。`-c` と `-m` の意味は `man wc` で調べる）
8. `xxd -b` で、課題7のバイトを2進数で表示する。各文字の1バイト目の先頭のビットの並びと、その文字のバイト数の間に、どんな規則があるかを見つける。2バイト目以降の先頭のビットには、どんな共通点があるか
9. 自分の名前（ひらがな、漢字、ローマ字のそれぞれ）が何バイトになるかを、先に予想してから `xxd` と `wc -c` で確かめる。予想と違ったら、どこが違ったかを書く
10. `head -c 1000 /dev/zero > zero.bin` でファイルを作る（`>` は、結果をファイルに保存する記号。これもF3で学ぶ）。`ls -l` のサイズ、`wc -c` の結果、`xxd zero.bin | tail -3` の出力を見比べる。`/dev/zero` とは何か
11. `lscpu`、`free -h`、`df -h` を実行し、自分の環境のCPUの数、メモリの量、ストレージの空きを読み取る。CPU・メモリ・ストレージの役割を、それぞれ1文で書く。メモリとストレージは、電源を切ったときと速さの点で、どう違うか
12. `file /usr/bin/bash` と `file zero.bin`、自分で作ったテキストファイルに対する `file` の結果を比べる（テキストファイルは `printf 'hello\n' > hello.txt` で作れる）。`xxd /usr/bin/bash | head -1` の先頭4バイトは何を意味するか

### 発展（任意）

- `man xxd` で、16進ダンプを元のバイトの並びに戻すオプションを探す。`hello.txt` をダンプしてから元に戻し、同じ中身になることを確かめる
- 1KB、1MB、1GBは、それぞれ何バイトか。`free -h` と `df -h` の「h」を外すと、表示はどう変わるか
- 負の数を2進数でどう表すか（2の補数）を書籍で調べ、8ビットでの -1 を紙に書く

## 詰まりやすいところ

- 行の先頭に `>` が出て、プロンプト（入力待ちの表示）が戻らない → `'` の数が合っているかを疑う。抜けるのは Ctrl+C
- `printf 'A'` のあと、次のプロンプトが同じ行に続いて表示される → 課題5で調べた `echo` と `printf` の違いを思い出す
- `wc -c` と `wc -m` の結果が同じになる → `locale` を実行し、出力に `UTF-8` が含まれているかを確かめる
- `xxd` の左端の数が 10、20 と増えていく → その数が何進数で書かれているかを `man xxd` で確かめる
- `command not found` と出る → まず打ち間違いを疑う。`|` の前後、`-` とオプションの文字を1文字ずつ見直す
- `man` の画面から抜けられない → キーワードの節の最初の段落を見る
