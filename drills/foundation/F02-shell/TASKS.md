## ねらい

マウスを使わずに、ファイルとディレクトリを自由に扱えるようになる。閉域の現場のサーバーには、画面でファイルを操作する道具がないことが多く、つなぐ手段はターミナルだけになる。「今どこにいて、何があり、誰が読み書きできるか」を、コマンドだけで確かめられることが、以降のすべてのユニットの土台になる。

## このユニットで身につけること

- 今いる場所を確かめ、絶対パスと相対パスのどちらでも移動する
- ディレクトリとファイルを作り、コピーし、名前を変え、移動し、消す
- ワイルドカードで、複数のファイルをまとめて指定する
- `ls -l` の出力を読み、誰が何をできるファイルかを言う
- `chmod` で、パーミッションを数字と記号の両方で変える
- `find` で、名前や種類を条件にファイルを探す
- `man` から、目的のオプションを自分で見つける

## キーワード

分からない語は、まず `man コマンド名` か `コマンド名 --help` で調べる。

- **シェル**：打ったコマンドを受け取り、実行してくれるプログラム。Ubuntuの標準は `bash`
- **カレントディレクトリ**：今いるディレクトリ。`pwd` で表示できる
- **絶対パス**：いちばん上の `/` から書いた、ファイルの場所
- **相対パス**：カレントディレクトリから見た、ファイルの場所
- **ホームディレクトリ**：ユーザーごとの自分用のディレクトリ。`~` と書ける
- **ワイルドカード**：`*` や `?` で、複数のファイル名をまとめて表す書き方
- **パーミッション**：ファイルごとに決まっている「誰が、読む・書く・実行するのどれをできるか」
- **所有者・グループ・その他**：パーミッションを決める3つの区分
- **隠しファイル**：名前が `.` で始まるファイル。ふつうの `ls` には出ない

## 課題

1. `pwd`、`ls`、`ls -la`、`cd` を試す。`~`、`.`、`..`、`/` がそれぞれ何を指すかを、実際に `cd` して確かめ、メモに書く。引数なしの `cd` と、`cd -` は、どこへ移動するか。`ls` と `ls -la` で、表示されるファイルの数はなぜ違うか
2. 入力を楽にする：コマンドやパスを途中まで打って Tab キーを押すと、何が起きるか。候補が複数あるときは、どうなるか。↑キーと `history` で、前に打ったコマンドを呼び出す
3. `mkdir -p` を使い、`project/src`、`project/docs/img`、`project/tmp` を作る。`find project` で、できあがった構造を表示する。`-p` を付けずに `mkdir a/b/c` を実行すると、どうなるか
4. `project/src` に空のファイルを3つ作る（`touch`）。1つをコピーし、1つの名前を変え、1つを `project/tmp` に移動し、最後に `project/tmp` をディレクトリごと消す。`rm -r` がなぜ危険かを書く。`rm -i` は何をするか。消したファイルを元に戻す方法はあるか
5. 毎回の始めに打っている決まり文句の `cp -n` を調べる。コピー先に同じ名前のファイルがあるとき、`cp` と `cp -n` で、結果はどう違うか。中身の違う2つのファイルで実際に試し、`man cp` の説明と照らし合わせる
6. 同じファイルを、絶対パスと相対パスの両方で `ls -l` する。`cd` で別の場所に移動したあと、もう一度両方を試す。結果が変わるのはどちらか
7. `*.txt` や `file?.txt` のようなワイルドカードで、複数のファイルをまとめて `ls` する（試すためのファイルは、先に `touch` でいくつか作る）。`echo *.txt` を実行すると何が起きるか。そこから、ワイルドカードを展開しているのは誰だと言えるか
8. `ls -l` の各列の意味を調べる。`rwxr-xr-x` を数字に直す。ファイルを作り、`chmod` で `644`、`600`、`755`、`u+x`、`go-r` を順に試し、そのたびに `ls -l` で確かめる。`r`、`w`、`x` がそれぞれ 4、2、1 なのはなぜか（F1の2進数で考える）
9. 中身が `echo hello` だけのファイル `hello.sh` を作る（VS Codeで作るか、F1で使った `>` で作る）。`./hello.sh` で実行しようとすると何が起きるか。実行できるようにする
10. `find ~/sandbox -name '*.txt'`、`-type d`、`-newer` を試す（`-newer` の後ろに何を書くかは `man find` で調べる）。`-name '*.txt'` の `'` を外すと、結果が変わることがある。どんなときか
11. `man ls` を読み、「サイズの大きい順」「更新の新しい順」「人が読みやすい単位で」の表示方法を見つける。`man` の中で文字列を検索する方法も調べる
12. **本題**（仕上げ）：課題3〜9と同じ操作を、自分で10個の指示リストにして `checklist.md` に書く（例：「`work/a` と `work/b` を一度に作る」。コマンドそのものは書かない）。次回のウォームアップで、何も見ずにその10個をこなす

### 発展（任意）

- ディレクトリを作り、`chmod` でそのディレクトリの `x` を外す。`cd` と `ls` は、それぞれどうなるか。`r` だけを外した場合と比べる（終わったら元に戻す）
- 新しく作ったファイルのパーミッションは、なぜ毎回同じ値になるのか。`umask` を調べる
- `ln -s` でシンボリックリンク（別の場所を指す、名前だけのファイル）を作り、`ls -l` での見え方を確かめる

## 詰まりやすいところ

- `cd` や `ls` で `No such file or directory` → `pwd` で今いる場所を確かめ、打ったパスが絶対か相対かを見直す
- ディレクトリが `rm` で消せない → エラーメッセージを読み、`man rm` でディレクトリを扱うオプションを探す
- `./hello.sh` で `Permission denied` → `ls -l hello.sh` の左端の列を読む
- 空白を含む名前のファイルを指定すると、2つの別のファイルとして扱われる → 名前を引用符で囲んだ場合と比べる
- `ls *.txt` で `No such file or directory` → カレントディレクトリに当てはまるファイルがあるかを、`ls` で確かめる
- `man ls` の内容や見た目が書籍と違う → 「平日に読むもの」の注意書きを読む。オプションの意味は、実際に試して確かめる
