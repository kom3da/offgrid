## ねらい

1つのテーブルから、「欲しい行を、欲しい列だけ、欲しい順に」取り出せるようになる。障害の調査でも、データの確認でも、最初に打つのは `SELECT`。言葉で言われた要望を、その場で `SELECT` に直せることが、SQL のいちばんの基礎になる。

## このユニットで身につけること

- 表示する列を選び、列に別名を付ける
- `WHERE` で、数値・文字列・日付の条件を書く。`AND`、`OR`、`NOT`、`IN`、`BETWEEN` を使い分ける
- `LIKE` で、前方一致・後方一致・部分一致の検索をする
- `ORDER BY` で、昇順・降順、複数の列での並べ替えをする
- `LIMIT` と `OFFSET` で、先頭のN件や、途中のN件だけを取り出す
- 結果の行数を、実行前におおまかに予想し、実行後に確かめる

## キーワード

- **`SELECT` 文**：テーブルから行を取り出す文。`SELECT`（列）→ `FROM`（テーブル）→ `WHERE`（条件）→ `ORDER BY`（並び順）→ `LIMIT`（件数）の順に書く
- **述語（じゅつご）**：`WHERE` に書く、真か偽かが決まる条件式
- **文字列リテラル**：SQL の中に直接書く文字列。一重引用符 `'` で囲む。二重引用符 `"` は別の意味になる
- **`LIKE`**：文字列のパターン検索。`%` と `_` が特別な意味を持つ
- **昇順・降順**：小さい順（`ASC`）と大きい順（`DESC`）
- **`LIMIT`・`OFFSET`**：取り出す件数と、読み飛ばす件数

## 平日に読むもの

- 『SQL ゼロからはじめるデータベース操作』の、`SELECT` 文の基本、算術演算子と比較演算子、論理演算子、並べ替えを扱う章

- `psql` の中の `\h SELECT`（長いので、`WHERE`、`ORDER BY`、`LIMIT` の部分だけ）

7. `LIMIT 10` を、`ORDER BY` ありとなしで実行する。「上位10件」と言えるのはどちらか。なぜか
8. **本題**：次の10問を、1問ずつ `q01.sql`〜`q10.sql` に書いて実行する。実行の前に、結果の行数を予想して `notes.md` に書く。実行後に、実際の行数と、先頭3行を記録する

## 詰まりやすいところ

- `column "PG" does not exist` のようなエラーになる → 値を囲んでいる引用符の種類を確かめる
- `LIKE` の結果が0行になる → データの大文字・小文字と、`%` を付けた位置を確かめる
- `AND` と `OR` を混ぜたら、行数が思ったより多い → かっこを付けて、評価の順を自分で決める
- 実行するたびに、先頭の10行が違う気がする → `ORDER BY` があるか、並べ替えの列に同じ値の行がないかを確かめる
- エラーメッセージの `LINE 1:` と `^` が何を指しているか分からない → `^` の位置の直前の語を疑う
