## ねらい

データベースを「表の集まり」として捉え、`psql` という対話ツールだけで、中を見て回れるようになる。閉域の現場では、画面つきの管理ツールを入れられないことが多い。`psql` と、その中のヘルプ（`\?`、`\h`）だけで操作できれば、どのサーバーでも同じように仕事ができる。

## このユニットで身につけること

- F10 で起動したコンテナの `psql` に入り、出る
- データベース、テーブル、列、行の関係を、自分の言葉で説明する
- メタコマンド（`\l`、`\c`、`\dt`、`\d テーブル名`、`\x`、`\?`、`\h`）で、今どこにいて、何があるかを調べる
- データベースとテーブルを作り、数行を入れ、中身を見て、削除する
- SQL の文を `.sql` ファイルに書き、コマンドラインから実行する
- サンプルDBの pagila を読み込み、次のユニットから使える状態にする

## キーワード

分からない語は、`psql` の中の `\?`（メタコマンドの一覧）と `\h コマンド名`（SQL の書式）で調べる。

- **データベース（DB）**：テーブルをまとめて入れておく入れ物。1つの PostgreSQL の中に、いくつも作れる
- **テーブル（表）**：行と列でできたデータの置き場所。表計算ソフトの1枚のシートに近い
- **列（カラム）**：テーブルの縦の並び。名前と型（入れられる値の種類）を持つ
- **行（レコード）**：テーブルの横の並び。1件ぶんのデータ
- **SQL**：データベースに対する命令を書く言語。文の終わりに `;` を付ける
- **メタコマンド**：`\` で始まる、`psql` 自身への命令。SQL ではないので `;` は要らない
- **スキーマ**：テーブルなどの定義（どんな表に、どんな列があるか）のこと。PostgreSQL では「テーブルを入れる名前空間」の意味でも使う

## 課題

1. `psql` に入り、`\?` でメタコマンドの一覧を出す。一覧の中での移動と終了のしかたを確かめる（F3 の `less` と同じ操作が使えるか）。`\q` で出て、もう一度入る
2. `\l` でデータベースの一覧を見る。最初からあるデータベースの名前を書き出す。`\conninfo` で、今どのデータベースに、どのユーザーでつないでいるかを確かめる。プロンプト（`postgres=#`）の `postgres` は、何を表しているか
3. `\h` とだけ打つと、何が出るか。`\h CREATE DATABASE` と `\h CREATE TABLE` を読み、書式のうち、角かっこ `[ ]` で囲まれた部分が何を意味するかを調べる
4. `drill` という名前のデータベースを作る。`\l` で増えたことを確かめ、`\c` でそのデータベースに移る。プロンプトはどう変わるか
5. `drill` の中に、自分の持ち物を記録するテーブルを1つ作る（列は3つ以上。文字の列、整数の列、日付の列を含める）。`\dt` と `\d テーブル名` で、作ったとおりになっているかを確かめる
6. 作ったテーブルに、3行以上を入れる。全部の行を表示する。`\x` を打ってからもう一度表示すると、見え方はどう変わるか。どんなときに `\x` が便利か
7. わざと間違える。次のそれぞれで、何が起きるか。エラーメッセージを書き写す
   - 文の最後の `;` を付けずに Enter を押す（プロンプトの記号はどう変わるか。どうすれば抜けられるか）
   - 整数の列に、文字を入れようとする
   - 存在しないテーブルを表示しようとする
8. テーブル名や列名を大文字で書いた場合と、小文字で書いた場合で、結果は変わるか。`SELECT` を `select` と書いた場合はどうか
9. **本題**：課題4〜6（データベースを作る、テーブルを作る、行を入れる、表示する）を `create.sql` に、テーブルの削除とデータベースの削除を `drop.sql` に書き、「準備」の形で順に実行する。`drop.sql` の実行後、`\l` に `drill` が残っていないことを確かめる。`.sql` ファイルの中で、つなぐ先のデータベースを切り替えるには、どう書けばよいか
10. `drill` につないだまま、`drill` を削除しようとすると、どうなるか。なぜか
11. pagila を読み込む。`pagila` という名前のデータベースを自分で作ってから、次を実行する

    ```sh
    docker exec -i pg-offgrid psql -U postgres -d pagila < ~/sandbox/pagila/pagila-schema.sql
    docker exec -i pg-offgrid psql -U postgres -d pagila < ~/sandbox/pagila/pagila-data.sql
    ```

    `psql` で `pagila` につなぎ、`\dt` でテーブルの一覧を見る。`\d film` と `\d customer` を読み、列の名前と型を `notes.md` に書き出す。`-d pagila` は、何の指定か

### 発展（任意）

- `\dt+` と `\l+` は、`+` なしと比べて何が増えるか。pagila でいちばん大きいテーブルはどれか
- `psql` の `-c` オプションを調べ、シェルから1行で、`film` テーブルの行数を表示する
- `\e` と `\i` は何をするメタコマンドか。`\?` で調べて試す（コンテナの中にエディタがない場合、何が起きるか）

## 詰まりやすいところ

- 何を打っても結果が出ず、プロンプトが `postgres-#` や `postgres'#` になっている → プロンプトの記号の意味を、`psql` のリファレンスの「プロンプト」の話題で調べる。入力を捨てるメタコマンドを `\?` で探す
- `docker exec` が「コンテナが動いていない」という意味のエラーになる → `docker ps -a` で状態を見る（F10）
- `.sql` ファイルを流したら、途中でエラーが出たのに最後まで進んだ → `-v ON_ERROR_STOP=1` を付けたかを確かめる
- `.sql` ファイルで作ったはずのテーブルが見当たらない → どのデータベースにつないで実行したかを疑う。`\conninfo` と `\l`
- 表示が横に長すぎて読めない → `\x` と、`\?` の「書式設定」の部分を見る

## 完了条件の確かめ方

次回のウォームアップで、何も見ずに（使ってよいのは `\?` と `\h` だけ）次をやる。データベースを作る → つなぐ → テーブルを作る → 2行入れる → 表示する → テーブルを削除する → データベースを削除する → `\l` で消えたことを確かめる。10分以内にできれば完了。
