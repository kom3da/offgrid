## ねらい

たくさんの行を、「何件あるか」「合計はいくらか」「グループごとにどうか」という数字にまとめられるようになる。F3 では `sort | uniq -c` でログを数えた。同じことを、データベースの中のデータに対して SQL で行う。監視でも売上でも、人が見たいのは1行ずつではなく、まとめた数字であることが多い。

## このユニットで身につけること

- `COUNT`、`SUM`、`AVG`、`MIN`、`MAX` で、テーブル全体を1行にまとめる
- `GROUP BY` で、グループごとに集計する。2つ以上の列でグループを作る
- `WHERE`（集計の前に行を絞る）と `HAVING`（集計の後にグループを絞る）を使い分ける
- 集計の結果を `ORDER BY` で並べ替え、「多い順の上位N件」を出す
- 日時の列から「月」を取り出して、月ごとに集計する
- 集計の結果が正しいかを、別の方法で検算する

## キーワード

- **集約関数**：複数の行を受け取り、1つの値を返す関数（`COUNT`、`SUM`、`AVG`、`MIN`、`MAX`）
- **`GROUP BY`**：指定した列の値が同じ行を、1つのグループにまとめる
- **`HAVING`**：グループに対する条件。集約関数を条件に使える
- **集約キー**：`GROUP BY` に書いた列のこと。`SELECT` に書ける列は、集約キーか集約関数だけ
- **`COUNT(*)` と `COUNT(列)`**：前者は行数、後者はその列に値が入っている行の数
- **切り捨て（日時）**：日時の「月より細かい部分」を捨てて、月の初めにそろえること。月ごとの集計に使う

## 課題

1. `film` の行数、長さの平均・最小・最大、`replacement_cost` の合計を、1つの `SELECT` で出す。平均の小数点以下を2桁に丸める方法を、マニュアルの「算術関数と演算子」の節で探す
2. `rating` ごとの映画の本数を出す。次に、本数の多い順に並べる。F3 の `sort | uniq -c | sort -rn` と、どこが対応しているか
3. `rating` ごとの本数を出す `SELECT` に、タイトルの列を足すと、どうなるか。エラーメッセージを書き写し、なぜ書けないのかを自分の言葉で説明する
4. `rating` ごとに、長さの平均とレンタル料金の平均を出す。長さの平均が、ある値（結果を見て、一部の `rating` だけが残るように自分で決める）を超える `rating` だけを残す。この条件を `WHERE` に書くと、どうなるか
5. `WHERE` と `HAVING` の違いを確かめる。「長さが 60 分以上の映画だけを対象にして、`rating` ごとの本数を出し、本数が一定以上（しきい値は、結果を見て自分で決める）の `rating` だけを残す」を書く。どの条件をどちらに書いたか。入れ替えて書けるものと、書けないものはどれか
6. `rental` で、`COUNT(*)` と、返却日の列を指定した `COUNT` の結果を比べる。なぜ違うか
7. 顧客ごとの支払いの回数と合計金額を出し、合計金額の多い順に上位10人を表示する（顧客は `customer_id` のままでよい。名前を付けるのは D4）
8. 2つの列でグループを作る。`film` で、`rating` とレンタル料金の組み合わせごとの本数を出す。結果は何行になると予想するか。実行して確かめる
9. `payment` の支払日時から、「月」の単位にまとめた値を作る方法を2つ探して試す（一部を取り出す方法と、切り捨てる方法）。年をまたぐデータがあった場合、どちらが安全か。なぜか
10. `staff` の全部の行を表示し、スタッフと店舗の対応を確かめる。`payment` には店舗の列がないので、このユニットでは「担当スタッフ（`staff_id`）ごとの集計」を「店舗別」とみなしてよい。そうみなせる理由と、みなせなくなるのはどんなときかを `notes.md` に書く（テーブルをつないで正しく店舗別にするのは D4）
11. **本題**：pagila で「月別・店舗別の売上合計」を出す。1行が「月、店舗（課題10の意味で）、売上合計、支払いの件数」になり、月の古い順、同じ月の中では店舗の順に並ぶようにする。`monthly-sales.sql` に保存する
12. 検算：課題11の各行の売上合計をすべて足した値（行数は少ないので、手計算か、結果をファイルに出して F3 の `awk` で足せばよい）と、`payment` 全体の金額の合計が一致することを確かめる。一致しなければ、どこで行が落ちたか、または増えたかを探す

## 詰まりやすいところ

- `must appear in the GROUP BY clause or be used in an aggregate function` というエラーが出る → `SELECT` に書いた列を1つずつ、集約キーか集約関数かに分類してみる
- `WHERE` に集約関数を書いてエラーになる → 条件が「1行ごと」に決まるものか、「グループごと」に決まるものかを考える
- 平均が、整数のように見える、または小数点以下が長すぎる → 列の型と、丸める関数を確かめる
- 月ごとにまとめたつもりが、行数がほとんど減らない → `GROUP BY` に書いた式が、元の日時のままになっていないかを確かめる
- `SELECT` で付けた別名を、`WHERE` や `HAVING` で使えない → 文のどの部分が先に評価されるかを、書籍の説明で確かめる
