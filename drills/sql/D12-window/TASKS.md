## ねらい

「種別ごとの上位3件」「月ごとの売上と、その累計」のように、行をまとめずに、行ごとに「まわりの行を見た値」を付けられるようになる。`GROUP BY` はグループを1行に潰すが、ウィンドウ関数は元の行を残したまま順位や累計を足す。監視ダッシュボードの「直近の値と、その前の値との差」「サーバーごとの CPU 上位3台」は、すべてこの形で書く。結果を実行前に予想し、同順位や NULL でずれる箇所を、先に体で覚える。

## このユニットで身につけること

- `OVER` 句の `PARTITION BY` と `ORDER BY` が、それぞれ何を決めるかを説明する
- `ROW_NUMBER`、`RANK`、`DENSE_RANK` の違いを、同じ値が並ぶ行で確かめる
- 順位を付けたあと、外側で「上位N件」に絞る（D10 の CTE を使う）
- `SUM` を `OVER` と組み合わせて、累計を出す
- ウィンドウフレーム（`ROWS` と `RANGE`）の違いを、同じ値が並ぶ行で確かめる
- `GROUP BY` では書けない「行を残したまま、グループの集計値を並べる」問い合わせを書く

## キーワード

- **ウィンドウ関数**：行ごとに、「その行から見えるまわりの行（ウィンドウ）」に対して計算する関数。`関数() OVER (...)` の形で書く
- **`PARTITION BY`**：ウィンドウを区切る列。`GROUP BY` に似ているが、行はまとめられない
- **`ORDER BY`（`OVER` の中）**：ウィンドウの中の行の順番。順位や累計は、この順で決まる
- **`ROW_NUMBER`**：順番どおりに 1, 2, 3 と番号を振る。同じ値でも別の番号になる
- **`RANK`・`DENSE_RANK`**：同じ値には同じ順位を付ける。次の順位を飛ばすか、飛ばさないかが違う
- **累計**：先頭からその行までの合計。「今月までの売上」のような値
- **ウィンドウフレーム**：累計や移動平均で、「どこからどこまでの行」を計算に入れるかの指定。`ROWS BETWEEN ... AND ...` の形
- **ピア（peer）**：`ORDER BY` の値が同じ行のこと。`RANGE` と `ROWS` の違いに関わる

## 課題

1. `film` を長さの長い順に並べ、`ROW_NUMBER` で番号を付けて先頭20行を見る。次に、`OVER ()` の中を空にすると、番号はどう付くか。予想してから確かめる
2. 同じ長さの映画が複数ある行（先頭20行の中にある）について、`ROW_NUMBER`、`RANK`、`DENSE_RANK` の3列を並べて表示する。3つの数字がずれ始めるのはどの行か、ずれ方はどう違うか。予想してから確かめ、`predict.md` に書く
3. `PARTITION BY` を足して、`rating` ごとに、長さの長い順の順位を付ける。順位が 1 に戻るのはどこか。`ORDER BY` を外側にも付けないと、結果はどう並ぶか
4. 順位で絞る。課題3の結果から「各 `rating` の上位3本」だけを残したい。`WHERE` に順位の条件を直接書くと、何が起きるか（エラーメッセージを書き写す）。D10 の CTE を使って、順位を付けた結果を外側で絞る形に直す。`ROW_NUMBER` で絞った場合と `RANK` で絞った場合で、行数は同じか。予想してから確かめる
5. **本題**：「カテゴリごとに、貸出回数の多い映画の上位3本」を書く（テーブルは `category`、`film_category`、`film`、`inventory`、`rental`。つなぎ方は D4 の課題1の図）。結果の列は、カテゴリ名、タイトル、貸出回数、順位。行数を実行前に予想して `predict.md` に書く（カテゴリの数 × 3 になるはずか。ならないとしたら、なぜか）。`top3-per-category.sql` に保存する
6. 課題5で、同じ貸出回数の映画が4本目以降にあるカテゴリはあるか。`RANK` と `DENSE_RANK` と `ROW_NUMBER` で、それぞれ「上位3本」の行数がどう変わるかを、実行前に予想してから確かめる。「上位3件」と言われたとき、どれを使うべきかは、何によって決まるか
7. 累計。D3 の `monthly-sales.sql`（月別の売上合計）に、`SUM` を `OVER` で使って、その月までの累計の列を足す。最後の行の累計が、`payment` 全体の合計と一致することを確かめる（D3 の課題12）
8. フレームの違い。D4 の `monthly-sales-by-store.sql`（月と店舗の行が複数ある）に、月の順の累計を付ける。`ORDER BY` に月だけを書いたとき、同じ月の2つの店舗の行の累計は、同じ値になるか、違う値になるか。予想してから確かめ、`\h SELECT` のフレームの説明で、既定のフレームが何かを読む。`ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW` を明示すると、結果はどう変わるか
9. 移動平均。月別の売上に、「その月を含む直近3か月の平均」の列を足す（`ROWS BETWEEN 2 PRECEDING AND CURRENT ROW`）。先頭の2行は、何行の平均になっているか。それでよいか
10. `GROUP BY` との違い。「各映画のタイトルと長さと、その `rating` の平均の長さ」を、1行が1本の映画になる形で出す。`GROUP BY` で書こうとするとどうなるか（D3 の課題3）。ウィンドウ関数で書き、そこから「自分の `rating` の平均より長い映画」だけを取り出す
11. NULL と順位。`rental` を返却日の新しい順に `ROW_NUMBER` を付けると、返却日が NULL の行は何番になるか。D8 の `predict.md` を見ずに予想してから確かめる。NULL を末尾にする書き方を、`OVER` の中でも使えるか
12. ウィンドウ関数を使う問い合わせの `EXPLAIN`（D9）を出し、`WindowAgg` と、その下に並べ替えの節点（`Sort` か `Incremental Sort`）が出ることを確かめる。`PARTITION BY` の列で並べ替えが起きているのはなぜか

## 詰まりやすいところ

- `window functions are not allowed in WHERE` と言われる → 課題4。順位を付ける段階と、絞る段階を分ける
- 順位がすべて 1 になる → `OVER` の中の `ORDER BY` があるか。`PARTITION BY` の列が、行を1つに決める列（主キーなど）になっていないか
- 累計が、途中で同じ値の行が続く → 課題8。既定のフレームが、同順位の行をどう扱うかを読み直す
- 本題の行数が、カテゴリ数 × 3 より多い・少ない → JOIN の段階で行数を数える（D4）。順位の関数の種類（課題6）
- 貸出回数が、映画ではなく在庫（`inventory`）ごとに数えられている → `GROUP BY` の列と、「1本の映画に在庫が複数ある」関係を思い出す
- `ORDER BY` を外側に書いていないので、結果の順番が読みにくい → `OVER` の中の `ORDER BY` は、結果の並び順を保証しない（D2 の課題6）
