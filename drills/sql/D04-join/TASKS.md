## ねらい

複数のテーブルをつないで、1つの結果にできるようになる。そして、つないだ結果が何行になるかを、実行する前に予想できるようになる。JOIN の間違いは、エラーにならず「行が増える」「行が消える」という形で現れる。行数を予想する癖が、その間違いに気づくための、いちばん安い検査になる。

## このユニットで身につけること

- 2つのテーブルを、対応する列（主キーと外部キー）でつなぐ
- 3つ以上のテーブルを、順につなぐ
- `INNER JOIN` と `LEFT JOIN` の結果の違いを、行数で説明する
- 「相手がいない行」を `LEFT JOIN` で探す
- サブクエリを、`WHERE` の中と `FROM` の中で使う
- つないだ結果の行数を、元のテーブルの行数と関係（1対多、多対多）から予想する
- つないだ結果に、D3 の集約を組み合わせる

## キーワード

- **結合（JOIN）**：2つのテーブルの行を、条件に合う組み合わせで横に並べること
- **主キー**：テーブルの中で、行を1つに決められる列（例：`film_id`）
- **外部キー**：ほかのテーブルの主キーを指している列。`\d` の下のほうの `Foreign-key constraints` に出る
- **内部結合（`INNER JOIN`）**：両方のテーブルに相手がいる行だけを残す
- **外部結合（`LEFT JOIN`）**：左のテーブルの行は、相手がいなくても残す。相手の列は NULL（値なし）になる
- **`IS NULL`**：値が入っていないことを調べる書き方（NULL の詳しい性質は D8）
- **1対多・多対多**：テーブル同士の行の対応のしかた。多対多は、間にもう1つのテーブル（例：`film_actor`）を置いて表す
- **サブクエリ**：`SELECT` 文の中に、かっこで囲んで入れた別の `SELECT` 文
- **テーブルの別名**：`FROM` の中でテーブルに付ける短い名前。同じ名前の列を区別するのに使う

## 課題

1. `\d film`、`\d film_actor`、`\d actor`、`\d inventory`、`\d rental`、`\d customer` の外部キーの表示を読み、どのテーブルのどの列が、どのテーブルを指しているかを、紙か `notes.md` に線でつないだ図として描く
2. `film`、`actor`、`film_actor`、`inventory`、`rental`、`customer` の行数を、それぞれ数えて `predict.md` の先頭に書く。以降の予想は、この数字をもとにする
3. `film` と `language` を内部結合して、映画のタイトルと言語の名前を表示する。実行前に行数を予想する。同じ名前の列が両方のテーブルにあるとき、列をどう書き分けるか
4. `film` と `film_actor` を内部結合した結果の行数を予想してから、実行する。`film` の行数より増えたか、減ったか。なぜか
5. 結合の条件（`ON`）を書き忘れる、または常に真になる条件にすると、行数はいくつになるはずか。**小さいテーブル同士（`store` と `staff` など）で**予想してから確かめる。大きいテーブルでは試さない
6. 3つのテーブルをつなぎ、「ある俳優（自分で1人選ぶ）が出演した映画のタイトル」を、タイトルの順に表示する
7. 出演者が1人も登録されていない映画はあるか。`film` を左にして `film_actor` を `LEFT JOIN` した行数を予想し、内部結合（課題4）の行数と比べる。差の行数は、何を意味するか。その映画のタイトルを表示する
8. 在庫（`inventory`）が1本もない映画を探す。`LEFT JOIN` を使う書き方と、サブクエリを使う書き方の両方で書き、結果の行数が同じになることを確かめる
9. `LEFT JOIN` の左右のテーブルを入れ替えると、結果の行数は変わるか。課題7のテーブルで予想してから確かめる。`LEFT JOIN` のあとの `WHERE` に、右のテーブルの列に対する条件を書くと、外部結合の意味はどうなるか
10. サブクエリ：「長さが、全部の映画の平均より長い映画」の本数を出す。次に、`FROM` の中にサブクエリを置いて、「顧客ごとの支払合計」の平均を出す
11. D3 の「月別・店舗別の売上合計」を、`staff` と `store` をつないで、正しい店舗別に書き直す。D3 の結果と、行数と合計が一致するか。結合によって `payment` の行が増えたり減ったりしていないことを、どうやって確かめるか
12. **本題**：次の5つについて、行数を実行前に予想して `predict.md` に書き、そのあとで実行して、実際の行数と、外れた場合の理由を書く。内部結合は、数字で予想する。`LEFT JOIN` は、「内部結合の行数 ＋ 相手のいない左側の行の数」の形で式として予想し、実行後に、式のそれぞれの数を別の `SELECT` で確かめる
    - `customer` と `rental` の内部結合
    - `customer` を左にした `rental` との `LEFT JOIN`（貸出が1回もない顧客はいるか）
    - `inventory` と `rental` の内部結合
    - `inventory` を左にした `rental` との `LEFT JOIN`（一度も貸し出されていない在庫はあるか）
    - `actor`、`film_actor`、`film` の3つの内部結合に、「`rating` が G」の条件を付けたもの（これは幅のある予想でよい。どう見積もったかを書く）

### 発展（任意）

- 顧客の氏名と、その顧客の支払合計を、合計の多い順に10人表示する（D3 の課題7に、名前を付ける）
- 同じ姓の俳優の組を探す（`actor` を自分自身と結合する）。同じ組が2回出ないようにするには、どんな条件が要るか
- `IN` を使うサブクエリと、`EXISTS` を使うサブクエリで、課題8を書き比べる

## 詰まりやすいところ

- `column reference "..." is ambiguous` というエラーが出る → その列が、どのテーブルのものかを書いているかを確かめる
- 結合したら、合計金額が不自然に大きくなった → 結合の前後で行数を数え、1対多の「多」の側で行が増えていないかを疑う
- `LEFT JOIN` にしたのに、相手のいない行が出てこない → `WHERE` に、右のテーブルの列の条件を書いていないかを確かめる
- 結果がいつまでも返ってこない → 結合の条件が抜けていないかを疑う。止めるのは Ctrl+C
- サブクエリで `more than one row returned` というエラーが出る → そのサブクエリが返す行数と、それを受ける側の演算子（`=` か `IN` か）を確かめる

## 完了条件の確かめ方

課題12の5つの予想のうち、内部結合の2つ（1つ目と3つ目）が実際の行数とぴったり一致し、`LEFT JOIN` の2つは予想の式が成り立つことを確かめられ、5つ目は「なぜその幅で見積もったか」を `predict.md` に説明できていれば完了。外れたものがあれば、日を改めて、別のテーブルの組み合わせを自分で5つ選び、同じ形式でもう一度行う。
