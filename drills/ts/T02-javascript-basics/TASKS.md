## ねらい

Goで解いた問題を、JavaScriptでもう一度解く。2つ目の言語は、1つ目との「違い」に注目すると速く身につく。JavaScriptは、間違ったコードでもエラーを出さずに動き続けることが多い。AIに聞けない現場では、その「黙って変な値になる」場面を、あらかじめ自分の手で体験しておくことが、いちばんの備えになる。

## このユニットで身につけること

- Node.jsを入れ、`.js` ファイルを実行する。対話モード（REPL）で式を試す
- `let` と `const` で変数を作り、関数を2通りの書き方で定義する
- `===` と `==` の違いを、実際の比較結果で示す
- 配列とオブジェクトを作り、読み書きし、ループで回す
- G2の3問（FizzBuzz、素数判定、九九の表）と、G3の単語の集計を、Node.jsで動かす
- `undefined` が出てくる場面を見分け、スタックトレースからエラーの場所を読む
- GoとJavaScriptの違いを、自分の実験結果をもとに説明する

## キーワード

- **Node.js**：JavaScriptを、ブラウザの外（シェル）で動かすための実行環境
- **npm**：Node.jsに付いてくるパッケージ管理の道具。このユニットでは入っていることだけ確かめる（使うのはT5から）
- **REPL**：1行入力するとすぐ結果が返る対話モード。`node` とだけ打つと始まる
- **動的型付け**：変数に型がなく、値のほうに型がある方式。Goは静的型付け
- **`undefined` と `null`**：どちらも「値がない」を表す。何が違うかは課題で調べる
- **オブジェクト**：名前（キー）と値の組の集まり。Goの構造体とマップの両方の役を担う
- **アロー関数**：`=>` を使った関数の短い書き方
- **truthy / falsy**：`if` の条件に置いたとき、真として扱われる値・偽として扱われる値

## 課題

1. `node` でREPLを開き、四則演算、文字列の連結、`typeof` を試す。`1 / 3`、`0.1 + 0.2`、`7 / 2` の結果を、Goの場合と比べる。次に `hello.js` を作り、`console.log` で1行表示して `node hello.js` で実行する。Goの `go run` と比べて、実行までの手順は何が違うか
2. `let` と `const` で変数を作る。`const` の変数に代入し直すと、どうなるか（エラーの文を記録する）。`let` の変数に、数値のあとで文字列を代入すると、どうなるか。Goで同じことをすると、どうなるか。宣言していない変数を読むと、どうなるか
3. `1 == "1"`、`1 === "1"`、`0 == ""`、`null == undefined`、`null === undefined`、`NaN === NaN` の結果を予想してから、REPLで確かめる。今後どちらの演算子を使うかを決め、理由を `notes.md` に書く
4. 関数を、`function` を使う書き方とアロー関数の両方で書く。引数を2つ取る関数を、引数1つで呼ぶと、足りない引数は何になるか。3つで呼ぶと、どうなるか。`return` を書き忘れた関数の戻り値は何か
5. **本題**：G2の3問を、それぞれ別のファイルで書く（FizzBuzz、素数判定、九九の表）。出力の形式はGo版と同じにする。Go版の出力とNode.js版の出力を、それぞれファイルに保存し、`diff` で一致を確かめる
6. 配列を作り、要素の追加、長さの取得、`for` 文と `for...of` 文でのループを試す。範囲の外の添字（たとえば長さ3の配列の10番目）を読むと、どうなるか。書き込むと、どうなるか。Goのスライスで同じことをすると、どうなるか
7. 配列の `map`、`filter` を使って、「1から20のうち、偶数だけを2乗した配列」を作る。同じものを `for` 文でも書き、読みやすさを比べる。`[10, 9, 1, 100]` を `sort()` で並べ替えた結果を予想してから、確かめる。なぜそうなるか。数の大小で並べるには、どうするか（MDNの `Array.prototype.sort` を読む）
8. オブジェクトを作り、プロパティの読み書きを、ドットと角かっこの2通りで行う。存在しないプロパティを読むと、どうなるか。あとからプロパティを足せるか。Goの構造体・マップと比べて、何が同じで何が違うか。キーと値をすべて表示する方法を、MDNの `Object` のページで探す
9. **本題**：G3の「文章中の単語を数えて、多い順に並べる」を書く。文章はG3と同じものを使い、コードの中に文字列として書いてよい。結果がGo版と一致することを確かめる。件数が同じ単語の並び順は、Go版と同じになったか。ならないとしたら、なぜか
10. 配列を別の変数に代入し、片方に要素を足すと、もう片方はどうなるか。オブジェクトではどうか。数値や文字列ではどうか。`const` で宣言した配列に要素を足せるのは、なぜか。Goの配列・スライス・マップの場合と比べる
11. `if` の条件に、`0`、`""`、`"0"`、`[]`、`{}`、`null`、`undefined`、`NaN` を1つずつ置き、真偽を一覧にする。Goでは、`if` の条件に数値を書けるか
12. わざとエラーを出す：存在しない関数を呼ぶ。`undefined` のプロパティを読む。表示されたスタックトレースから、ファイル名と行番号を読み取る（G7の復習）。`try` / `catch` で捕まえると、どうなるか。Goの `error` を返す方式と比べて、「エラー処理を書き忘れたとき」の動きはどう違うか

### 発展（任意）

- 単語の集計を、オブジェクトではなく `Map` を使って書き直す。どちらが向いているか
- 文章を、コードの中ではなくファイルから読む（Node.jsのドキュメントで `fs` の `readFileSync` を調べる）
- 素数判定を、2から10000までのすべての数に対して行い、`console.time` で時間を測って、Go版と比べる

## 詰まりやすいところ

- 数の足し算のはずが、`"12"` のように文字がつながる → 足している値それぞれの `typeof` を表示して確かめる
- 九九の表の桁がそろわない → Goの `%2d` に当たるものが `console.log` にあるかを疑う。MDNで、文字列の幅をそろえるメソッドを探す
- 1行に続けて出力したいのに、`console.log` が毎回改行する → 1行ぶんの文字列を組み立ててから表示する方法を考える。または、Node.jsのドキュメントで `process.stdout` を調べる
- エラーは出ないのに、結果が `undefined` や `NaN` になる → 途中の値を1つずつ `console.log` で表示し、最初におかしくなる行を探す（printデバッグ）
- 単語の数がGo版と合わない → 区切り文字、大文字と小文字、句読点、空文字列の要素の扱いを、Go版と1つずつ見比べる
