## ねらい

Webページの骨組み（HTML）と見た目（CSS）を、道具に頼らず手で書けるようになる。閉域の現場では、テンプレートやCSSフレームワークを後から取ってこられない。崩れた画面を前にしたとき、ブラウザの開発者ツールで「どの要素に、どのスタイルが効いているか」を自分の目で確かめられることが、この先のすべてのユニットの土台になる。

## このユニットで身につけること

- HTML文書の最小の形を、何も見ずに書く
- 見出し、段落、リスト、リンク、表、フォームを、意味に合った要素で書く
- CSSを別ファイルに分け、要素・クラス・IDのセレクタでスタイルを当てる
- ボックスモデル（余白と枠）を、開発者ツールの図で読む
- Flexboxで、横並びの2カラムを作る
- 開発者ツールのElementsパネルで、要素と、効いているスタイル・打ち消されたスタイルを見分ける
- ページが外部のサーバーに何も取りに行っていないことを確かめる

## キーワード

分からない語は、DevDocsに保存したMDNで調べる。

- **要素とタグ**：`<p>` と `</p>` で囲んだひとまとまりが要素。囲む記号がタグ
- **属性**：タグの中に書く追加の情報（`href`、`id`、`class` など）
- **セレクタ**：CSSで「どの要素に当てるか」を指定する書き方
- **ボックスモデル**：要素を、内容・`padding`・`border`・`margin` の4層の箱として扱う考え方
- **Flexbox**：子要素を1方向に並べ、幅の配分を決めるCSSの仕組み
- **開発者ツール**：ブラウザに内蔵の調査道具。多くのブラウザでは F12 キーで開く
- **Elementsパネル**：今のページの要素の木と、各要素に当たっているCSSを見る画面（Firefoxでは「インスペクター」）
- **オリジン**：スキーム・ホスト・ポートの組（`http://localhost:8000` など）。T4で重要になる

## 準備

```sh
cd ~/offgrid-log/drills/ts/T01-html-css
touch index.html style.css notes.md
python3 -m http.server 8000
```

サーバーはUbuntu（VMまたはWSL2）の中で動く。ブラウザはホスト側（WindowsやmacOS）のものを使い、`http://localhost:8000/` を開く。シェルをもう1つ開き、編集はそちらで行う。エディタのAI機能と、HTMLの自動補完の雛形（`!` で展開されるものなど）は使わない。

## 課題

1. HTML文書の最小の形（文書型の宣言、`html`、`head`、`body`、`title`、文字コードの指定）を `index.html` に書き、ブラウザで開く。`title` は、画面のどこに出るか。サーバー側のシェルには、何が表示されたか（F9の復習）
2. 自己紹介ページの中身を書く。見出し（`h1` と `h2` を使い分ける）、段落、順序なしリスト（学んだこと）、順序つきリスト（これから学ぶ順）、リンクを入れる。題材は公開してよい内容だけにする
3. 表を足す。これまでに終えたユニット（ID、テーマ、終えた月）を、見出し行つきの表にする。`thead`、`tbody`、`th`、`td` の役割を調べる
4. フォームを足す（名前、メールアドレス、好きな言語の選択、ひとこと、送信ボタン）。`label` の `for` と、入力欄の `id` を対応させると、何が変わるか（ラベルをクリックして確かめる）。`input` の `type` を `text`、`email`、`number` に変えて、空や不正な値で送信したときの違いを見る
5. 課題4のフォームを送信すると、ブラウザのアドレス欄と、サーバー側のログはどうなるか。`method` を `post` に変えると、どう変わるか。`python3 -m http.server` は、なぜそのステータスコードを返すのか（F9の表で確かめる）
6. CSSの当て方は3通りある（タグの `style` 属性、`style` 要素、別ファイル）。3つとも試したあと、別ファイル（`style.css`）に統一する。要素セレクタ、クラスセレクタ、IDセレクタで、同じ段落に違う色を指定したとき、どれが勝つか。書く順番を入れ替えると、結果は変わるか
7. ボックスモデル：見出しと表のセルに、`margin`、`padding`、`border` を指定する。開発者ツールで要素を選び、箱の図（ボックスモデルの表示）で、それぞれの値が何pxになっているかを読む。`box-sizing` を変えると、`width` の指す範囲はどう変わるか
8. **本題**：Flexboxで2カラムにする。左にプロフィール（名前とリスト）、右に本文（表とフォーム）を置く。左は決まった幅、右は残りの幅いっぱいになるようにする。カラムの間に、すき間を空ける。ブラウザの幅を変えても、この関係が保たれることを確かめる
9. 開発者ツールのElementsパネルで、次を行う
   - 左カラムの要素を選び、幅を決めているCSSの宣言が、どのファイルの何行目かを読む
   - 宣言のチェックを外す、値を書き換える、を試す。ページを再読み込みすると、どうなるか。なぜか
   - 取り消し線が付いた宣言を1つ見つけ、何に打ち消されたのかを調べる
   - Computed（計算済み）の表示で、`h1` の文字サイズが最終的に何pxかを読む
10. わざと壊す：閉じタグを1つ消す。CSSのプロパティ名を1文字間違える。存在しないクラス名を指定する。それぞれ、画面と開発者ツールには、どう現れるか。「ページのソースを表示」で見える内容と、Elementsパネルの内容は、どこが違うか
11. 閉域の確認：開発者ツールのNetworkタブを開いて再読み込みし、読み込まれたファイルの一覧を見る。`localhost` 以外への通信が1つもないことを確かめる。フォントは `font-family` で、端末に入っているものだけを指定する。Webフォント（Google Fontsなど）を使うと、閉域では何が起きるか

### 発展（任意）

- 画面の幅が狭いときだけ、2カラムを縦1列に並べ替える（MDNで、メディアクエリを調べる）
- 表の行に、1行おきに背景色を付ける。どんなセレクタを使えばよいかを、MDNの擬似クラスの一覧から探す
- `header`、`main`、`aside`、`footer` などの要素で書き直す。`div` との違いは何か

## 詰まりやすいところ

- ブラウザで `http://localhost:8000/` が開けない → サーバーが動いているか、どのアドレスとポートで待ち受けているかを `ss -ltn` で確かめる（F8）。VMの場合は、ポートの転送の設定を疑う
- CSSを直したのに、画面が変わらない → Networkタブで、`style.css` が本当に読み直されているか、ステータスコードは何か（F9の304）を見る
- 日本語が文字化けする → ファイルを保存した文字コードと、HTMLで宣言した文字コードを見比べる（F1）
- Flexboxが効かない → `display` を指定した要素と、並べたい要素の親子関係を、Elementsパネルの木で確かめる
- スタイルが当たらない → Elementsパネルでその要素を選び、自分の書いた宣言が一覧に出ているか、出ていて取り消し線が付いているか、を切り分ける

## 完了条件の確かめ方

完成したページを開き、開発者ツールだけを使って（CSSファイルをエディタで開かずに）、次の3つに答えを出し、`notes.md` に書く。

- 右カラムの、今の幅は何pxか。その幅を決めているのは、どの要素のどの宣言か
- 表のセルの `padding` は上下左右それぞれ何pxか
- ページの中で、取り消し線の付いた（打ち消された）宣言はどれで、勝ったのはどの宣言か

加えて、開発者ツールの上で左カラムの幅を一時的に変え、2カラムが保たれることを確かめる。次回のウォームアップで、HTMLの最小の形とFlexboxの2カラムを、何も見ずに書く。

## 残すもの

- `index.html`、`style.css`
- `notes.md`（各課題で分かったこと、完了条件の3つの答え）
- 画像を使った場合は、自分で用意したものだけを同じディレクトリに置く（外部のURLを参照しない）

ファイルは、リポジトリの中のこのディレクトリに、AI機能を切ったエディタで書く。この `TASKS.md` はカリキュラムの一部なので、書き換えない。
