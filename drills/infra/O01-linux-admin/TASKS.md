## ねらい

初めて触るサーバーに入ったとき、「このマシンは何者で、今どんな状態か」を、最初から入っているコマンドだけで調べられるようになる。閉域の現場では、監視ツールも検索もないまま、状況の把握から始めることが多い。持ち込むファイルが壊れていないかを確かめる方法も、ここで身につける。

Stage 4からは、AIなしデーのWeb検索は0回。調べる手段は `man`、`--help`、書籍、保存しておいたドキュメントだけになる。

## このユニットで身につけること

- ユーザーとグループを作り、所属を確かめ、消す
- `sudo` が「誰に、何を」許しているかを読む
- ディスクの空きと、容量を食っているディレクトリを調べる
- ログがどこに、誰の権限で置かれているかを調べる
- `/proc/stat` と `/proc/meminfo` を読み、CPUとメモリの状態を数字で言う
- スクリプトを、決まった時刻に自動で動かす
- ファイルをまとめ（`tar`）、壊れていないかを確かめ（`sha256sum`）、別のマシンへ送る（`scp` か `rsync`）
- 上の調べ方を、1本のスクリプトにまとめる

## キーワード

- **UID・GID**：ユーザーとグループに付く番号。ファイルの持ち主は、名前ではなくこの番号で記録されている
- **`sudo`**：一時的に、別のユーザー（ふつうは管理者の root）としてコマンドを実行する仕組み
- **`/proc`**：カーネル（OSの中心部分）が持っている情報を、ファイルの形で見せている場所。ディスク上には実体がない
- **ロードアベレージ**：実行待ちのプロセスが、平均でいくつあるかを表す数字
- **cron**：決まった時刻にコマンドを実行する、昔からある仕組み
- **systemd timer**：同じことを systemd（O2で詳しく扱う）で行う仕組み
- **アーカイブ**：複数のファイルを1つにまとめたもの。`tar` で作る
- **ハッシュ値（チェックサム）**：ファイルの中身から計算する短い文字列。中身が1ビットでも変わると、まったく違う値になる
- **サービス**：裏で動き続けるプログラム（Webサーバー、DBなど）

## 課題

1. `id`、`groups`、`getent passwd "$USER"` を実行し、自分のUID、GID、所属グループを書き出す。`/etc/passwd` の1行は `:` で区切られている。それぞれの部分が何を表すかを `man 5 passwd` で調べる。`/etc/shadow` を `cat` すると、どうなるか。なぜか
2. 練習用のユーザー `drill01` を作る。`man useradd` で、ホームディレクトリを一緒に作るオプションと、ログインシェルを指定するオプションを探す。作ったあと、`/etc/passwd`、`/etc/group`、`/home` がどう変わったかを確かめる。`useradd` と `adduser` は、何が違うか
3. グループ `drillers` を作り、`drill01` を追加する（`man groupadd`、`man usermod`）。`usermod` でグループを追加するとき、あるオプションを付け忘れると、元の所属グループから外れてしまう。どのオプションかを `man` で確かめてから実行する。最後に、`drill01` と `drillers` を消す（`man userdel` で、ホームディレクトリも消すオプションを探す）
4. `sudo -l` で、自分に許されていることを読む。`sudo cat /etc/sudoers` と `ls /etc/sudoers.d/` で設定を読む（**編集はしない**）。自分が `sudo` を使えるのは、どの行のおかげか。`man sudoers` で、設定を編集するときに `visudo` を使う理由を調べる
5. `df -h` と `df -i` の違いは何か。`du` で、`/var` の直下のディレクトリを、容量の大きい順に並べる（F3のパイプを使う。深さを1段に限るオプションを `man du` で探す）。`sudo` を付けた場合と付けない場合で、結果はどう違うか。なぜか
6. `ls -l /var/log` で、ログのファイルを眺める。認証（ログインや `sudo`）の記録、OS全体の記録、パッケージ操作（`apt`）の記録は、それぞれどのファイルか。持ち主とパーミッションはどうなっているか。`sudo` を1回実行し、その記録を見つける
7. `/proc/meminfo` を読む。`MemTotal`、`MemFree`、`MemAvailable` の違いを `man` で調べ、`free -h` の出力と見比べる。`/proc/stat` の先頭の `cpu` の行を、1秒あけて2回表示する。どの数字が増えたか。それぞれの列が何を表すかを調べる。`/proc/loadavg` と `uptime` の出力も見比べる
8. `tar` で、`~/sandbox/o1` の中に作った適当なディレクトリを、圧縮つきのアーカイブにする。展開せずに中身の一覧を見る方法、別のディレクトリに展開する方法を `man tar` で探す。`sha256sum` でハッシュ値をファイルに保存し、`-c` で検証する。アーカイブの末尾に1バイト足してから（`echo >> ファイル`）、もう一度検証すると、どうなるか
9. 課題8のアーカイブとハッシュ値のファイルを、`scp` か `rsync` で `localhost` の別のディレクトリへ送り、送り先で検証する。`rsync` を選んだ場合は、同じコマンドを2回実行して、2回目に何が転送されるかを観察する。閉域の現場へファイルを持ち込むとき、ハッシュ値は「いつ」「どこで」計算し、「どこで」検証するべきか
10. **本題**：`sysinfo.sh` を書く。次の7つを、見出しを付けて標準出力に出す。`set -euo pipefail` を付け、`shellcheck` の指摘が0件になるまで直す
    - OSの名前とバージョン、カーネルのバージョン、ホスト名、起動してからの時間
    - ディスクの使用状況
    - メモリの合計と、使える量（`/proc/meminfo` から取り出す）
    - ログインできるユーザーの一覧（ログインシェルが `nologin` や `false` でないもの）
    - 待ち受けている（LISTEN の）ポートと、分かる範囲でプロセス名
    - 動いているサービスの一覧（`man systemctl` で、種類と状態で絞り込むオプションを探す）
    - 主なログの場所と、それぞれの大きさ
11. `sysinfo.sh` を、`sudo` なしで実行した場合と `sudo` ありで実行した場合で、出力のどこが変わるかを比べる。`sudo` なしでも、エラーで止まらずに最後まで動くようにする
12. `sysinfo.sh` の出力を、日付入りのファイル名で `~/sandbox/o1/reports/` に保存する処理を、5分おきに自動で実行する。cron と systemd timer のどちらか一方を選ぶ（`man 5 crontab` か `man systemd.timer`）。2回以上実行されたことを確かめたら、設定を消す。定期実行のときと、手で実行したときで、環境変数 `PATH` は同じか

### 発展（任意）

- 課題12を、選ばなかったほうの仕組みでもやり、設定の書き方と、実行結果の確認のしかたの違いをまとめる
- `/proc/stat` を1秒あけて2回読み、その差からCPU使用率（%）を計算するスクリプトを書く。`top` の表示と比べる
- `sysinfo.sh` に、使用率が90%を超えたディスクがあれば終了コード1で終わるオプションを付ける

## 詰まりやすいところ

- ユーザーをグループに追加したのに、`groups` の結果が変わらない → その設定が「いつ」読み込まれるかを疑う（F10で `docker` グループに入ったときと同じ）
- `du` が `Permission denied` を大量に出す → 標準エラー出力だけを捨てる方法（F3）。捨てた場合、合計の数字は信用できるか
- cron で動かすと、手で動かしたときには出なかった「コマンドが見つからない」が出る → cron が用意する環境変数を `man 5 crontab` で調べる。cron の実行記録がどのログに出るかも調べる
- `ss` の出力で、プロセス名の列が空になる → 他人のプロセスの情報を見るのに必要な権限を疑う
- `set -e` のせいで、`grep` が1件も見つけなかっただけでスクリプトが止まる → `grep` の終了コードを `man grep` で調べる
- `scp` や `rsync` で `localhost` につながらない → `ss` で22番ポートが LISTEN になっているか、`systemctl status ssh` はどうか

## 完了条件の確かめ方

- `shellcheck sysinfo.sh` の指摘が0件
- `./sysinfo.sh` を `sudo` なしで実行し、7つの見出しがすべて出力され、終了コードが0（`echo $?`）
- 課題12で保存されたファイルが2つ以上ある（`ls` の結果を `notes.md` に貼る）
- 次回のウォームアップで、「メモリの使える量を `/proc/meminfo` から取り出す1行」を、何も見ずに書く

## 残すもの

- `sysinfo.sh` と、その出力の例（`sysinfo-sample.txt`。ホスト名やユーザー名をコミットしたくなければ、その部分を伏せる）
- 各課題で使ったコマンドと、観察したこと（`notes.md`）
- 課題12の設定内容（crontab の1行、または timer の設定）を `notes.md` に写したもの
- アーカイブそのものはコミットしない

コマンドを試す場所は `~/sandbox/o1`。メモとスクリプトは、リポジトリの中のこのディレクトリに、AI機能を切ったエディタで書く。この `TASKS.md` はカリキュラムの一部なので、書き換えない。
