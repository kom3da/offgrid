## ねらい

関係のある値を1つにまとめる構造体と、値の置き場所を指すポインタを使えるようになる。「関数に渡したのに、値が変わらない」「変えるつもりがないのに、変わった」という不具合は、値がコピーされるのか、共有されるのかの理解で決まる。AIなしで原因を突き止めるために、コピーと共有の違いを、自分の目で観察しておく。

## このユニットで身につけること

- `&` で変数の置き場所（アドレス）を取り出し、`*` でその先の値を読み書きする
- 関数に値を渡す場合と、ポインタを渡す場合の違いを確かめる
- 構造体を定義し、フィールドに名前を付けて、値を作る
- 構造体にメソッドを付ける
- 値レシーバとポインタレシーバで、動きがどう変わるかを観察し、使い分ける
- 不正な操作（残高を超える出金など）を、呼び出した側に伝える
- 複数の構造体を、スライスやマップに入れて扱う

## キーワード

- **ポインタ**：値そのものではなく、値の置き場所を指すもの。型は `*int` のように書く
- **アドレス**：メモリの上での、値の置き場所を表す番号。`&x` で取り出せる
- **デリファレンス**：ポインタが指している先の値を、`*p` で読み書きすること
- **構造体（`struct`）**：名前の付いた複数の値（フィールド）を、1つにまとめた型
- **メソッド**：特定の型に結び付けた関数。`口座.入金(1000)` のような形で呼ぶ
- **レシーバ**：メソッドが結び付いている相手。値で受ける（値レシーバ）か、ポインタで受ける（ポインタレシーバ）かを選ぶ
- **値渡し**：関数に値を渡すとき、コピーが渡されること。Goの引数は、すべてこの方式
- **コンストラクタ関数**：構造体を正しい初期状態で作って返す関数。Goでは、`New〜` という名前にする習慣がある

## 課題

1. `int` の変数 `x` を作り、`&x` を表示する。ポインタの変数 `p` に `&x` を入れ、`*p` を表示する。`*p` に別の値を代入すると、`x` はどうなるか。紙に、`x` と `p` の箱と矢印の図を描く
2. 値を入れずに宣言しただけのポインタ（`var p *int`）の中身は何か。その `*p` を読むと、何が起きるか。止まったときのメッセージを記録する
3. `int` を受け取って1を足す関数と、`*int` を受け取って、その先に1を足す関数を書く。それぞれを呼んだあと、呼び出した側の変数は変わっているか。なぜか
4. 名義（`string`）と残高（`int`、単位は円）を持つ構造体を定義する。フィールド名を付けて値を作り、`fmt.Printf` の `%v`、`%+v`、`%#v` で表示して、違いを見る。値を入れずに宣言した構造体の中身は、どうなっているか。残高を `float64` ではなく `int` で持つのは、なぜか（`0.1 + 0.2` を `float64` の変数で計算して表示する。2進数で小数を表すと何が起きるかを、『プログラムはなぜ動くのか』で確かめる）
5. 構造体の変数 `a` を、別の変数 `b` に代入してから、`b` の残高を変える。`a` は変わるか。`b` を `&a` にした場合は、どうか。課題1の図に描き足す
6. 口座に、残高を返すメソッドと、入金するメソッドを付ける。入金は、**まず値レシーバで**書き、1000円を入金してから残高を表示する。どうなったか。次に、ポインタレシーバに書き換えて、もう一度確かめる
7. 出金するメソッドを付ける。残高より多い額の出金、0円以下の入金と出金は、受け付けない。受け付けなかったことを、呼び出した側が分かるようにする（伝え方は自分で決める。`error` を使う書き方はG6で学ぶので、ここでは `bool` を返す形でよい）
8. 名義と最初の残高を受け取り、口座を作って返す関数を書く。最初の残高が負のときは、どう扱うかを決めて、`notes.md` に理由を書く
9. 口座を3つ、スライスに入れる。`for range` で、全員に100円ずつ入金してから、全員の残高を表示する。入金は反映されたか。反映されない場合、なぜか。直し方を2通り考えて、試す
10. 振込：口座Aから口座Bへ、指定した額を移す関数を書く。Aの残高が足りないときは、AもBも変わらないこと。次の場合を実行して、結果を `notes.md` に貼る：成功する、残高が足りない、額が0以下、AとBが同じ口座
11. 名義から口座を引けるように、マップに入れる。`map[string]口座の型` のマップの要素のフィールドに、直接代入しようとすると、コンパイラは何と言うか。`map[string]*口座の型` にすると、どうなるか
12. **本題**：何も見ずに、`explain.md` に「値レシーバとポインタレシーバの違い」を書く。課題6で観察したこと、なぜそうなるか（コピーされるもの）、どちらを選ぶかの自分なりの基準を含める

### 発展（任意）

- 口座に、取引の履歴（種類、額、取引後の残高）をスライスで持たせ、一覧で表示するメソッドを付ける
- `type Yen int` のように、構造体でない型を定義して、メソッドを付ける。`Yen` の値と `int` の変数は、そのまま足せるか
- 構造体の埋め込みを『初めてのGo言語』で調べ、利率を持つ「定期口座」を、元の口座を埋め込んで作る
- `==` で、構造体どうしを比べられるか。ポインタどうしの `==` は、何を比べているか。スライスをフィールドに持つ構造体では、どうなるか

## 詰まりやすいところ

- メソッドを呼んだのに、値が変わらない → そのメソッドのレシーバが、値かポインタかを確かめる。メソッドの中と、呼び出した側の両方で、`&` を付けてアドレスを表示して比べる
- `invalid memory address or nil pointer dereference` というpanicで止まる → メッセージに出ている行で使っているポインタを、直前で表示してみる。どこで中身を入れたか（入れていないか）を追う
- `for range` の中で変えた値が、ループのあとで元に戻っている → ループの変数に入っているのは、スライスの要素そのものか、コピーかを、G3の課題6と同じ方法で確かめる
- `cannot assign to struct field ... in map` と出る → マップから取り出した値が、コピーなのかどうかを考える。課題11の2つの形を比べる
- `*` の意味が混乱する → 型の中に書く `*`（`*int`）と、式の中に書く `*`（`*p`）を、分けて表に整理する
- 振込で、片方の口座だけが変わってしまう → 失敗するかどうかを調べる処理と、実際に残高を変える処理の、順番を紙に書く
