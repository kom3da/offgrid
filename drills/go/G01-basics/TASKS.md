## ねらい

初めてのプログラミング言語として、Goのプログラムを自分の手で書き、動かせるようになる。閉域の現場では、エラーの意味を検索することも、AIに聞くこともできない。コンパイラ（ソースコードを実行できる形に変換するプログラム）のメッセージを自分で読み、手元のドキュメントだけで直す習慣を、最初のユニットから付ける。

## このユニットで身につけること

- Goが正しく入っているかを確かめ、モジュールを作って、プログラムを実行する
- `go run` と `go build` を使い分け、違いを自分の言葉で説明する
- 変数を宣言し、整数・小数・文字列・真偽値を扱う
- 四則演算を書き、型が違う値どうしの計算で何が起きるかを確かめる
- 引数と戻り値のある関数を書き、`main` から呼ぶ
- コンパイルエラーのメッセージから、ファイル名・行番号・原因を読み取る
- `go fmt` と `go vet` をかける。`go doc` で標準ライブラリの説明を引く

## キーワード

分からない語は、まず `go doc パッケージ名.名前`（例：`go doc fmt.Println`）と `go help コマンド名` で調べる。

- **コンパイル**：人が書いたソースコードを、コンピュータが実行できる形に変換すること。Goでは `go build` が行う
- **パッケージ**：関連するコードのまとまり。実行できるプログラムは `package main` から始まる
- **モジュール**：パッケージをまとめた、コードの管理単位。`go.mod` というファイルが目印になる
- **変数**：値に名前を付けて、入れておく場所
- **型**：値の種類（`int`、`float64`、`string`、`bool` など）。Goでは、変数ごとに型が決まっている
- **ゼロ値**：値を入れずに変数を宣言したときに、最初から入っている値
- **関数**：処理に名前を付けたもの。引数（入力）を受け取り、戻り値（出力）を返す
- **標準ライブラリ**：Goと一緒に入っているパッケージ群（`fmt` など）。追加のダウンロードなしで使える

## 準備

Goのインストールと、A Tour of Goの手元への導入は、ネットワークが要るので**平日に済ませておく**。インストールは公式サイトの「Download and install」の手順に従う（`uname -m` で自分のCPUの種類を確かめ、合うファイルを選ぶ）。Ubuntuの `apt` で入るGoは古いことがあるので、バージョンが1.22以上になる方法を選ぶ。G2 以降の確認で使う `go test -race` には C コンパイラが要るので、`sudo apt install -y build-essential` も平日に済ませておく。

```sh
cd ~/offgrid-log/drills/go/G01-basics

go mod init offgrid/g01-basics

```

プログラムは、1つにつき1つのディレクトリに分けて置く（`hello/main.go`、`calc/main.go`）。実行は `go run ./hello` の形で行う。

## 課題

1. `go version`、`which go`、`go env GOROOT GOPATH` の出力を `notes.md` に貼る。それぞれが何を表すかを `go help environment` で調べる
2. `go mod init` でできた `go.mod` の中身を読む。何が書かれているか。モジュールとは何かを、1〜2文で `notes.md` に書く
3. A Tour of Goの最初のHello Worldを、コピーせずに手で打って `hello/main.go` に書き、`go run ./hello` で動かす。次に、わざと1か所ずつ壊して、コンパイラが何と言うかを記録する（メッセージの「ファイル名:行:列」の部分が、どこを指しているかも確かめる）
   - `package main` の行を消す
   - 関数 `main` の名前を別の名前に変える
   - `import` の行を消す
   - 使っていないパッケージを `import` に足す
   - 文字列を閉じる `"` を消す
4. `go build ./hello` を実行する。何というファイルができたか。`ls -l` と `file` で調べ、`file` の出力に何と書かれているかを読む。できたファイルを `~/sandbox/g01` にコピーして、そこで実行できるか。`go run` のあとには、同じようなファイルが残るか
5. 変数：`var` を使う宣言と、`:=` を使う宣言の両方を書く。次のとき、コンパイラは何と言うか
   - 宣言した変数を、一度も使わない
   - `:=` を、関数の外で使う
   - `int` の変数に、文字列を代入する
   - 同じ名前の変数を、同じ場所で2回 `:=` で宣言する
6. `int`、`float64`、`string`、`bool` の変数を、値を入れずに宣言して表示する。それぞれのゼロ値は何か。`fmt.Printf` の `%T` と `%v` が何を表示するかを `go doc fmt` で調べ、使ってみる
7. 四則演算：`7 / 2`、`7.0 / 2`、`7 % 2` の結果を、実行する前に予想してから確かめる。`int` の変数と `float64` の変数を足そうとすると、どうなるか。計算できるようにするには、どうするか（型変換）
8. F1とのつながり：`int8` の変数に127を入れて、1を足すと、結果はどうなるか。`len("abc")` と `len("あいう")` の結果は、なぜ違うか。2進数とUTF-8の知識で説明する。あわせて、`const` で宣言した定数に、あとから別の値を代入しようとすると、どうなるかも確かめる
9. `calc/main.go` に、2つの整数を受け取って、和・差・積を返す関数を、それぞれ書く。`main` から呼んで、結果を表示する。戻り値の型を書き忘れると、コンパイラは何と言うか
10. 商と余りの**2つ**を同時に返す割り算の関数を書く。0で割ると何が起きるか。ソースコードに直接 `10 / 0` と書いた場合と、変数に入れた0で割った場合とで、エラーが出るタイミングはどう違うか
11. インデントをわざと崩してから `go fmt ./...` をかけ、何が変わるかを `git diff` で見る。`fmt.Printf` の `%d` に文字列を渡すコードを書き、`go run` の結果と、`go vet ./...` の指摘を比べる（確かめたら、元に戻す）
12. **本題**：何も見ずに、`explain.md` に「`go run` と `go build` の違い」を書く。できるファイル、実行のしかた、Goが入っていない別のマシンに持っていく場合にどちらを使うか、を含める

### 発展（任意）

- `go build -o` で、出力するファイルの名前を指定する。`go help build` で、ほかにどんなオプションがあるかを眺める
- `go doc math` から関数を3つ選び、使ってみる。`math.Sqrt` に `int` の変数を渡すと、どうなるか
- `go env GOOS GOARCH` の意味を調べる。閉域のサーバーに実行ファイルだけを持ち込む場合、何を確かめておく必要があるかを考えて書く

## 詰まりやすいところ

- `go: command not found` と出る → シェルがコマンドを探す場所（F4の環境変数 `PATH`）に、Goの `bin` が入っているかを確かめる
- `go: go.mod file not found` と出る → 今いるディレクトリと、`go.mod` のある場所を `pwd` と `ls` で確かめる
- `main redeclared` と出る → 同じディレクトリに、`main` 関数を持つファイルが2つないかを疑う
- エラーが何行も出て、どれから直せばよいか分からない → いちばん上の1つだけを直して、もう一度実行する
- `declared and not used` で先に進めない → Goが「使わない変数」をどう扱う言語かを、『初めてのGo言語』で確かめる
- 確認コマンドで `-race requires cgo` と出る → Cコンパイラ（`gcc`）が入っているかを `which gcc` で確かめる
