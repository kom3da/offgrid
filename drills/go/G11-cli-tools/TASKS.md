## ねらい

Stage 1で学んだことを全部使って、人に渡せるコマンドラインツールを2つ仕上げる。CSVの列を集計する `csvstat` と、アクセスログを集計する `logagg`。F3で `grep | sort | uniq -c` で出した答えを、今度はGoで出し、同じになることを自分で確かめる。閉域の現場では、「シェルの1行で済むこと」と「Goで書くべきこと」の境目を、自分で判断することになる。オプション、テスト、READMEがそろって初めて、ツールは他人（3か月後の自分）に渡せる。

## このユニットで身につけること

- `encoding/csv` で、引用符やカンマを含むCSVを正しく読む
- 列を指定して、件数・合計・最小・最大・平均・中央値を出す
- アクセスログの1行を、構造体に分解する関数を書き、テストする
- 上位N件、種類ごとの件数、時間帯ごとの件数を、マップと `slices.SortFunc` で出す
- `flag` でオプションを設計し、使い方を標準エラー出力に出し、終了コードを決める
- 壊れた入力を、行番号つきのエラーで報告する（G6）
- 他人が読んで使えるREADMEを書く
- 自分のツールとシェルのパイプラインの結果を、`diff` で突き合わせる

## キーワード

- **CSV**：カンマで区切ったテキストのデータ形式。カンマや改行を含む値は、`"` で囲む決まりがある
- **レコード／フィールド**：CSVの1行（レコード）と、その中の1つの値（フィールド）
- **ヘッダ行**：1行目に、列の名前を並べたもの。ある場合とない場合がある
- **中央値**：値を並べたときの、真ん中の値。個数が偶数のときの決め方は、自分で調べて決める
- **集計**：たくさんの行から、件数や合計のような少数の数字にまとめること
- **上位N件**：件数の多い順に並べて、先頭からN個を取ること
- **終了コード**：コマンドが終わるときに返す数。0が成功（F5）
- **README**：そのツールの目的、使い方、オプション、例を書いた、最初に読むファイル

`testdata/sales.csv` を、手で作る。ヘッダ行あり、列は「日付、商品名、数量、単価」の4つ、10行ほど。商品名の1つには、`"` で囲んだカンマ入りの名前を入れる。数量が空の行と、単価に数字でない文字が入った行も、わざと1行ずつ入れる。`csvstat` と `logagg` は、それぞれ `main` パッケージにし、中心の処理は `main` から分けて、`io.Reader` と `io.Writer` で受ける（G8）。

## 課題

1. `go doc encoding/csv` を読み、`testdata/sales.csv` を `csv.Reader` で読んで、レコード数と、各レコードのフィールド数を表示する。同じファイルを `strings.Split` でカンマ区切りにした場合と、カンマ入りの商品名の行で、何が違うか。フィールドの数が他の行と違う行を1つ足すと、`csv.Reader` は何を返すか。エラーに、行番号は入っているか（`go doc csv.ParseError`）
2. `csvstat` の使い方を、コードより先に `csvstat/README.md` に書く：`csvstat [オプション] [ファイル]`、ファイルがなければ標準入力。集計する列をどう指定するか（列名か、番号か、両方か）、ヘッダ行がないファイルをどう扱うか、区切り文字を変えられるか（タブ区切りも読めるか。`go doc csv.Reader` の `Comma`）、を決めて書く
3. `csvstat` の中心の関数を書く：`io.Reader` と列の指定を受け取り、件数・合計・最小・最大・平均・中央値を返す。数字に変換できないフィールドは、行番号と列名を含むエラーにする（G6の `%w`）。空のフィールドは、飛ばすのか、エラーにするのかを決め、READMEに書く。中央値のために、値の並べ替えが要る（G10）
4. 課題3のテーブル駆動テストを、文字列から読む形で書く（G8）。ケースには、ふつうのデータ、1行だけ、空のフィールド、数字でない値（エラーに行番号が含まれることを確かめる）、カンマ入りの引用符つきフィールド、ヘッダ行だけ、偶数個と奇数個の中央値、負の数、を含める
5. `csvstat` の `main` を書く。`flag` の定義、使い方の表示、終了コード（成功、入力が壊れている、ファイルが開けない、列の指定が間違っている）を決める。`awk`（F3）で同じ列の合計と平均を出し、`csvstat` の結果と比べる。小数の表示の桁が違うなら、どちらに合わせるか、桁を指定するオプションを付けるかを決める
6. `logagg` の設計：F3の課題1で調べた、ログの1行の各部分の意味を `notes.md` に写す。1行を「IPアドレス、時刻、メソッド、パス、ステータスコード、バイト数」の構造体に分解する関数を書く。`strings.Fields` で足りるか、`strings.Cut` や `strings.Index` が要るかは、行の形を見て決める。時刻から「時」だけを取り出す方法も考える（文字列の切り出しで済ませてよい。`time.Parse` を使うなら `go doc time.Parse` と `go doc time.Layout`）
7. 課題6の分解関数のテストを書く。ケースには、生成したログの本物の1行、ユーザーエージェントに空白が多いもの、フィールドが足りない壊れた行（エラーになること）、空行、を含める
8. 集計を書く：F3の課題6・7と同じ4つ。IPアドレスの上位N件、ステータスコードごとの件数、404になったパスの上位N件、時間帯ごとの件数。さらに、転送バイト数の合計。どれを出すかはオプション（例：`-top-ip 10`、`-status`、`-hour`）で選ぶ。出力の形は「件数 値」の順で、件数の多い順、件数が同じなら値の順（G10の課題12）にする。壊れた行は、飛ばして件数を標準エラー出力に出す。それぞれの集計に、`testdata/small.log` か文字列を入力にしたテストを付ける
9. **本題**：`compare.sh`（F5）を書く。F3の `notes.md` に残した1行のパイプラインと、`logagg` の出力を、4つの集計すべてについて `diff` で比べる。`uniq -c` の出力は件数が右寄せなので、比べる前に `awk` で整える。差が出たら、どちらが正しいのかを、ログを `grep` して確かめる。件数が同じ値の順番で差が出るなら、それはどちらの問題か
10. `time` で、5,000行の `testdata/access.log` と、`gen-access-log.sh 500000` で作った50万行のログについて、パイプラインと `logagg` の所要時間を比べる（50万行のログは `testdata/` の外、`~/sandbox/g11` に置く）。どちらが速いか。行数が100倍になったとき、それぞれ何倍かかったか。G10の言葉で説明する
11. `logagg/README.md` を書く。両方のREADMEに、目的、ビルドのしかた（`go build -o`）、使い方、オプションの一覧、実行例と出力例、終了コードの意味、壊れた入力の扱い、を入れる。書いたら、READMEだけを見て、その手順どおりに `~/sandbox/g11` でビルドして使ってみる。書いていないのに知っていないと使えないことが、1つでもないか
12. 2つのツールを見直す：`main` は薄いか。`flag` の説明文は、`-h` で読んで分かるか。`go vet` の指摘はないか。テストしにくくて `main` に残っている処理はないか。直したところを、`notes.md` に書く

### 発展（任意）

- `csvstat` で、複数の列を一度に集計できるようにする。`logagg` で、複数のログファイルを一度に読めるようにする（G8の `mygrep` と同じ考え方）
- 出力の形式を `-format csv` で切り替え、`logagg` の出力を `csvstat` に渡せるようにする
- `csvstat` に、95パーセンタイル（値を並べたときの、下から95%の位置の値）を足す。応答時間の分布を見るときの定番で、O9とC8で使う
- 圧縮されたログ（`gzip`）をそのまま読めるようにする（`go doc compress/gzip`）

## 詰まりやすいところ

- `csv.Reader` が `wrong number of fields` で止まる → ヘッダ行と本文の列数を数える。列数が行ごとに違うファイルを許すかどうかを、`go doc csv.Reader` のフィールドの一覧から決める
- `strconv.ParseFloat` が失敗する → 前後の空白、全角の数字、`1,000` のような桁区切り、を疑う。`%q` で表示すると、見えない文字が分かる
- 上位N件が、パイプラインの結果と順番だけ違う → 件数が同じ値が混ざっていないか。`sort -rn` が、同じ件数のときに何を基準にしているかを `man sort` で調べる
- `logagg` の分解関数が、一部の行だけ失敗する → 失敗した行をそのまま表示する。ユーザーエージェントやパスに、区切りと同じ文字が入っていないか
- 時間帯の集計が、F3の結果と1つずれる → 「時」を取り出している位置が、日付の桁数によって変わっていないか
- テストからテストデータが見つからない → G7の課題7（テスト実行時のカレントディレクトリ）

## 完了条件の確かめ方

```sh
go vet ./... && go test -race -cover ./...
go build -o bin/csvstat ./csvstat && go build -o bin/logagg ./logagg
./bin/csvstat -h; ./bin/logagg -h
./compare.sh && echo OK
```

- 2つのツールのテストがすべて通り、カバレッジが80%以上。異常な入力（壊れた行、数字でない値）のケースがある
- `-h` で、すべてのオプションの説明が読める。READMEの手順だけで、ビルドと実行ができる
- `compare.sh` で、4つの集計すべてが、F3のパイプラインと一致する
- `notes.md` に、課題10の所要時間の比較がある
