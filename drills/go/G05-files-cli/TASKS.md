## ねらい

ファイルを読み、オプションを受け取り、結果を出力する、本物のコマンドラインツールを、Goで作れるようになる。閉域の現場では、足りない道具を、自分で作って持ち込むことがある。Stage 0で使い込んだ `wc` を題材にして、「本物と同じ結果になるか」を自分で確かめながら作る。

## このユニットで身につけること

- コマンドライン引数を受け取る（`os.Args`、`flag`）
- ファイルを開いて、読んで、閉じる。開けなかった場合を処理する
- `bufio` で、ファイルを1行ずつ、または1単語ずつ読む
- ファイルが指定されなければ、標準入力から読む
- 結果は標準出力に、エラーは標準エラー出力に書き、終了コードで成功と失敗を伝える
- 自作のコマンドの結果を、本物のコマンドの結果と比べて、検証する

## キーワード

- **CLI**：コマンドラインインターフェース。ターミナルから、文字で操作するプログラム
- **コマンドライン引数**：コマンド名のあとに並べて渡す値。Goでは `os.Args` に入る
- **フラグ**：`-l` のような、動きを切り替えるオプション。`flag` パッケージで扱う
- **標準入力**：プログラムが、最初から持っている入力元。キーボードや、パイプの左側につながる（`os.Stdin`）
- **バッファ**：読み書きを効率よくするために、データを一時的にためる場所。`bufio` の名前の由来
- **`defer`**：関数が終わるときに実行する処理を、先に予約する書き方。閉じ忘れを防ぐために使う
- **終了コード**：プログラムが終わるときに、シェルに返す数。0が成功（F5）。Goでは `os.Exit` で指定する

## 課題

1. `os.Args` の中身を、1つずつ番号つきで表示するプログラムを書く。引数なし、引数3つ、空白を含む引数（引用符で囲む）で実行する。0番目には何が入っているか。`go run` で実行した場合と、`go build` したものを実行した場合とで、違いはあるか
2. `os.ReadFile` で、ファイルをまるごと読んで表示する。戻り値は2つある。2つ目は何か。存在しないファイルを指定すると、2つ目には何が入るか。読み込んだデータの型は何か。`string` にするには、どうするか
3. `os.Open` でファイルを開き、`bufio.Scanner` で1行ずつ読んで、行番号つきで表示する（`cat -n` と見比べる）。ファイルを閉じる処理を、`defer` で書く。`defer` を書く位置を、開けたかどうかを確かめる前にすると、何がまずいかを考える
4. 課題3を元に、行数を数える。`testdata/access.log` の結果を、`wc -l` と比べる
5. `bufio.Scanner` の区切り方を、単語ごとに変える方法を `go doc bufio.Scanner` と `go doc bufio.ScanWords` で調べ、単語数を数える。`wc -w` と比べる
6. バイト数を数える。まず「各行の長さの合計」で数えて、`wc -c` と比べる。一致するか。しなければ、差はいくつで、その差は何の数か
7. `testdata/` に、次のファイルを作る（作り方も調べる。`printf` が使える）。それぞれで、自作の結果と `wc` を比べる。合わないものがあれば、`man wc` で「行数」の定義を読み直す
   - 空のファイル
   - 最後の行の終わりに、改行がないファイル
   - 空行だけが3行あるファイル
   - 日本語を含むファイル（`wc -c` と `wc -m` の違いも確かめる）
8. `flag` パッケージで、`-l`（行数）、`-w`（単語数）、`-c`（バイト数）を受け取る。何も指定されなければ、3つとも表示する。`-h` を付けて実行すると、何が表示されるか。定義していないフラグを渡すと、どうなるか。フラグ以外の引数（ファイル名）を取り出す方法を、`go doc flag` で探す
9. 複数のファイルを受け取り、ファイルごとの結果と、最後に合計の行を表示する。存在しないファイルが混じっていたら、そのファイルのエラーを標準エラー出力に出し、残りのファイルは処理を続け、最後に0以外の終了コードで終わる。本物の `wc` の動き（メッセージの出る先と `echo $?`）と比べる
10. ファイル名が1つも指定されなければ、標準入力から読む。`cat testdata/access.log | go run ./mywc` と `go run ./mywc < testdata/access.log` の両方で確かめる
11. **本題**：`go build -o mywc ./mywc` でビルドし、課題7のファイル、`access.log`、`/etc/passwd`、自分の `main.go` のそれぞれで、`-l`、`-w`、`-c` の数値を、本物の `wc` と比べるシェルスクリプト `compare.sh` を書く（F5。`shellcheck` にかける）。1つでも違えば、どのファイルのどの数が違うかを表示して、終了コード1で終わる

### 発展（任意）

- 文字数を数える `-m` を足す（`go doc unicode/utf8`）
- いちばん長い行の長さを表示する `-L` を足す。`wc -L` と比べる
- 全角の空白で区切った日本語のファイルで、単語数は `wc -w` と一致するか。一致しなければ、「空白」の定義がそれぞれどうなっているかを、`go doc unicode.IsSpace` と `man wc` で調べる
- 行数の数え方を、`bufio.Scanner` を使う方法と、改行のバイトを数える方法の2通りで書き、20万行のログ（`gen-access-log.sh 200000`）で `time` を比べる

## 詰まりやすいところ

- 改行で終わらないファイルで、行数が1つ多い → `wc -l` が何を数えているかを、`man wc` で確かめる。`bufio.Scanner` が、最後の行をどう扱うかを確かめる
- バイト数が、行数の分だけ少ない → `bufio.Scanner` が返す行に、何が含まれていないかを、`go doc bufio.ScanLines` で確かめる
- `no such file or directory` と出る → `pwd` で今いる場所を確かめ、相対パスがどこから見た道順かを考える
- フラグが効かない → フラグを定義しただけで、読み取る処理（`go doc flag.Parse`）を呼んでいるか。ファイル名より前に、フラグを書いているか
- 何も表示されず、プロンプトも戻らない → 標準入力を待っていないかを疑う（入力の終わりは Ctrl+D）
- とても長い行のあるファイルで、途中で読むのをやめてしまう → ループのあとに `go doc bufio.Scanner.Err` を調べているか。`bufio.Scanner` の行の長さの上限を、`go doc` で探す

## 完了条件の確かめ方

```sh
go vet ./... && go build -o mywc ./mywc && ./compare.sh; echo $?
```

`compare.sh` が、すべてのファイルで「行数・単語数・バイト数が一致」と判定し、終了コード0で終わる。比べるのは数値で、桁をそろえる空白の数までは合わせなくてよい。
