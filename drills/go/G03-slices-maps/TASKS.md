## ねらい

たくさんの値をまとめて扱う、スライスとマップを使えるようになる。ログの集計も、設定の読み込みも、ほとんどのプログラムは「並べて持つ」と「名前で引く」の組み合わせでできている。F3でシェルのパイプを使ってやった「数えて、多い順に並べる」を、今度はGoで書く。

## このユニットで身につけること

- スライスを作り、要素の追加・取り出し・繰り返しをする
- `len` と `cap` の違いを、`append` で値を足しながら観察する
- `make` で、長さや容量を指定して、スライスとマップを作る
- スライスの一部を切り出したとき、元のスライスと何を共有するかを確かめる
- マップで、キーから値を引く。キーがないときの動きを確かめる
- マップを繰り返したときの順番の性質を知り、決まった順に並べて表示する
- `strings` パッケージの関数を、`go doc` で探して使う

## キーワード

- **配列**：同じ型の値を、決まった個数だけ並べたもの。Goでは、直接使うことは少ない
- **スライス**：長さを変えられる、値の並び。裏側にある配列の、一部分を見ている
- **長さ（`len`）と容量（`cap`）**：今入っている要素の数と、裏側の配列に入れられる数
- **`append`**：スライスの末尾に要素を足す、組み込み関数（`go doc builtin.append`）
- **`make`**：スライスやマップを、大きさを指定して作る、組み込み関数（`go doc builtin.make`）
- **マップ**：キー（見出し）と値の組を入れておく入れ物。ほかの言語では、辞書や連想配列と呼ばれる
- **`nil`**：「何も指していない」ことを表す値。スライスとマップのゼロ値
- **panic**：実行中に、続けられない誤りが起きて、プログラムが止まること（メッセージの詳しい読み方はG7）

## 課題

1. 配列 `[3]int` と、スライス `[]int` を、それぞれ作って表示する。範囲の外の番号を、数字で直接指定した場合と、変数で指定した場合とで、エラーの出るタイミングとメッセージはどう違うか。配列とスライスで、違いはあるか
2. 空のスライスに、`append` で1から20までを1つずつ足しながら、毎回 `len` と `cap` を表示する。`cap` はどんなふうに増えるか。`append` の結果を、元の変数に代入し忘れると、どうなるか
3. `make([]int, 5)` で作ったスライスと、`make([]int, 0, 5)` で作ったスライスに、それぞれ `append` で1を足して表示する。結果はどう違うか。なぜか
4. スライス `s` から `s[1:3]` を切り出して、別の変数 `t` に入れる。`t` の要素を書き換えると、`s` はどうなるか。`t` に `append` すると、`s` はどうなるか。予想してから確かめる。共有しない写しを作る方法を、`go doc builtin.copy` で調べて試す
5. 値を入れずに宣言しただけのスライス（`var s []int`）と、`[]int{}` で作ったスライスを比べる。`len`、`nil` との比較、`append` できるか、をそれぞれ確かめる
6. `for range` で、スライスの番号と値を表示する。ループの中で、値を受け取った変数を2倍にすると、元のスライスは変わるか。元のスライスを2倍にするには、どう書くか
7. マップ：`map[string]int` を作り、値を入れる、取り出す、消す（`go doc builtin.delete`）、個数を数える。入れていないキーを取り出すと、何が返るか。「値が0」と「キーがない」を見分ける書き方を調べる。`var m map[string]int` と宣言しただけのマップから読むと、どうなるか。書き込むと、どうなるか
8. 5つ以上のキーを入れたマップを `for range` で表示するプログラムを、5回実行する。順番は毎回同じか。キーの順に表示するには、どうするか（`go doc slices.Sort`）
9. `go doc strings` の一覧から、次のことができる関数を探して試す：空白で単語に分ける、小文字にそろえる、両端の記号（`.`、`,`、`(` など）を取り除く
10. **本題** 単語の集計：文章中の単語を数えて、件数の多い順に、上位10語を「件数 単語」の形で表示する。大文字と小文字は区別しない。件数が同じ単語は、アルファベット順に並べる。並べ替えは `go doc slices.SortFunc` を読んで使う（比べるための関数を、自分で書いて渡す）
11. 同じ文章（`text.txt`）を、F3で学んだパイプでも集計し、上位5語と件数が、Goの結果と一致するかを確かめる（空白を改行に変えるコマンドは `man tr` で調べる）。一致しなければ、単語の区切り方と記号の扱いの、どこが違うかを調べる
12. **本題**：何も見ずに、`explain.md` に「`append` と `make` の使い方」を書く。`append` の結果を代入する理由、`len` と `cap` の違い、`make` の引数の意味、課題3で見た違い、マップを `make` で作る理由を含める

## 詰まりやすいところ

- `index out of range` というpanicで止まる → メッセージにある番号と長さを読む。その行で、スライスの `len` を表示してみる
- `append` したのに、増えていない → `append` の戻り値を、どこに入れているかを確かめる
- 先頭にゼロが並んだスライスになる → `make` の2つ目と3つ目の引数の意味を、`go doc builtin.make` で確かめる
- `assignment to entry in nil map` というpanicで止まる → そのマップを、どこで作ったか（宣言しただけではないか）を確かめる
- 実行するたびに、出力の順番が変わる → マップを繰り返すときの順番について、『初めてのGo言語』のマップの話題を読む
- 件数の順に並べる方法が分からない → 並べ替えられるのは、マップではなくスライス。「何のスライスを作れば、並べ替えの途中で件数を見られるか」を考える
