## ねらい

「もし〜なら」と「〜の間くり返す」を組み合わせて、小さな問題を自分の頭で解けるようになる。どんなに大きなプログラムも、この2つの組み合わせでできている。FizzBuzz、素数判定、九九の表を、何も見ずに書けることが、AIなしで書く力の最初の土台になる。

## このユニットで身につけること

- `if`、`else if`、`else` で、条件によって処理を分ける
- `for` の3つの形（回数を決める、条件だけ、無限）を使い分ける
- `break` と `continue` で、ループの流れを変える
- `switch` で、多くの分岐を読みやすく書く
- ループの中にループを入れて（二重ループ）、表の形の出力を作る
- `fmt.Printf` で、桁をそろえて表示する
- 書く前に、紙に日本語で手順を書く。動かす前に、結果を予想する

## キーワード

- **条件式**：結果が `true` か `false` になる式。`==`、`!=`、`<`、`<=` などの比較で作る
- **論理演算子**：条件をつなぐ `&&`（かつ）、`||`（または）、`!`（でない）
- **剰余（`%`）**：割り算の余り。「〜で割り切れるか」の判定に使う
- **ループ**：同じ処理をくり返すこと。Goでは `for` だけで書く
- **無限ループ**：終わる条件がなく、止まらないループ。止めるのは Ctrl+C（F4）
- **スコープ**：変数が使える範囲。`{ }` の中で宣言した変数は、その外では使えない
- **境界値**：条件の境目になる値（0、1、ちょうど上限の値など）。間違いが起きやすい

## 課題

1. 整数の変数を1つ用意し、正・負・ゼロのどれかを表示する `if`、`else if`、`else` を書く。値を変えて、3つとも通ることを確かめる。`if` の条件に `int` の変数をそのまま書く（`if x { }`）と、コンパイラは何と言うか
2. `if` の `{ }` の中で宣言した変数を、その外で使おうとすると、どうなるか。`if` の条件の前に、短い文（`:=` の宣言）を書ける形を、A Tour of Goで調べて試す
3. `for` で、1から10までを表示する。同じことを、条件だけの `for` と、無限の `for` に `break` を組み合わせた形でも書く。`break` を書き忘れた無限ループを、わざと実行して、止める
4. 1から20までのうち、偶数だけを表示する。`continue` を使う書き方と、使わない書き方の両方で書く
5. **本題（その1）** FizzBuzz：1から100までを、1行に1つずつ表示する。3の倍数は `Fizz`、5の倍数は `Buzz`、両方の倍数は `FizzBuzz`、それ以外は数そのもの。書く前に、紙に日本語で手順を書く。条件を調べる順番を入れ替えると、結果はどう変わるか。なぜか
6. FizzBuzzの分岐を、`switch` で書き直す。条件を書かない `switch`（`switch { case 条件: }` の形）を調べて使う。Goの `switch` は、`case` の終わりで次の `case` に進むか
7. **本題（その2）** 素数判定：整数を受け取り、素数なら `true` を返す関数を書く。まず、2からその数の手前まで、全部で割ってみる方法で書く。0、1、2、負の数を渡したとき、正しい答えになるか
8. 課題7の関数を使って、100未満の素数をすべて表示し、個数を数える（25個になる）。10000未満では1229個になる。次に、割ってみる範囲を減らす方法を考える。ループが回った回数を数える変数を足し、減らす前と後の回数を比べる
9. **本題（その3）** 九九の表：1の段から9の段までを、9行9列で表示する。まず、桁をそろえずに書く。次に、`fmt.Printf` の幅の指定で、列をそろえる。`go run ./kuku | wc -l` と、`awk` で各行の列の数を数えて、形を確かめる
10. 二重ループの中の `break` は、どのループを抜けるか。予想してから、確かめる。外側のループまで抜けたいときの書き方（ラベル）を、『初めてのGo言語』で調べる
11. 3つのプログラムそれぞれに、わざと境界の間違い（`<` と `<=` の取り違え、開始が0か1か）を入れ、出力がどう変わるかを `diff` で見る。自分がやりやすい間違いを `notes.md` に書く

### 発展（任意）

- FizzBuzzの上限を、コマンドライン引数で受け取る（`go doc os.Args`、`go doc strconv.Atoi`）。数でないものが渡されたら、メッセージを出して終わるだけでよい（エラーの詳しい扱いはG6）
- 2つの整数の最大公約数を求める関数を、ループで書く
- 九九の表に、見出しの行と列、区切りの線を付ける
- 1からNまでの合計を、ループで求める関数と、公式で求める関数を書き、結果が同じになるかを確かめる

## 詰まりやすいところ

- プログラムが終わらない → ループの条件に使っている変数が、ループの中で変わっているかを確かめる。変数の値を毎回表示してみる
- 出力が1つ多い、または1つ少ない → ループの開始の値と、終了の条件（`<` か `<=` か）を、紙の上で最初の2回と最後の2回だけなぞる
- FizzBuzzで `FizzBuzz` が一度も出ない → 15のとき、上から順にどの条件に最初に当たるかを、声に出してなぞる
- `else` の行でコンパイルエラーになる → `}` と `else` の位置関係を、A Tour of Goの例と見比べる。`go fmt` をかけてみる
- 素数判定で、1や2の結果がおかしい → ループが1回も回らない場合に、関数が何を返すかを確かめる
- 九九の列がずれる → 1桁の数と2桁の数で、幅がどうなっているかを見る。`go doc fmt` で幅の指定を探す

## 完了条件の確かめ方

1. 最初に書いた3つの出力を、`go run ./fizzbuzz > fizzbuzz.txt` のようにして、ファイルに保存しておく
2. 別の回（またはウォームアップ）に、空のディレクトリ `retry/` を作り、本・メモ・前のコード・A Tour of Goを閉じた状態で、3つをゼロから書く。見てよいのは、コンパイラのメッセージと `go doc` だけ。かかった時間を計る
3. 書き直した3つの出力を、保存したファイルと `diff` で比べ、差がない（素数は、100未満の一覧と個数で比べる）
4. `go vet ./...` が何も指摘しない

3つとも、`go doc` 以外を見ずに書けたら完了。1つでも見てしまったら、日を空けてもう一度やる。
