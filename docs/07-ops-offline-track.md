# Stage 4：運用と閉域トラック

Stage 0の知識とGo・DBを結びつけ、「ネットワークがなくても開発・デプロイできる」状態を作る。systemdや`strace`はLinux専用なので、このステージはLinux環境（仮想マシン、WSL2、検証用サーバー）で行う。課題は `drills/infra/<ユニット>-<名前>/` に置く。

| ユニット | テーマ | 課題 | 完了条件 |
| --- | --- | --- | --- |
| O1 | Linuxの管理 | ユーザーとグループ、`sudo`、ディスク（`df`、`du`）、ログの場所 | 新しいサーバーの状態を一通り確認できる |
| O2 | systemd | G12〜G17で作ったAPIをsystemdのサービスにし、`systemctl`と`journalctl`で操作する | 再起動後も自動で起動する |
| O3 | 調査ツール | `ss`、`lsof`、`strace`、Goの`pprof` | わざと起こした障害の原因を特定できる |
| O4 | Dockerfile | マルチステージビルド、`CGO_ENABLED=0`の静的バイナリ、distrolessイメージ | イメージサイズ30MB以下 |
| O5 | docker compose | API・PostgreSQL・リバースプロキシをまとめて起動する | `docker compose up`だけで全体が動く |
| O6 | IaC入門 | Terraform（またはOpenTofu）かAnsibleで、O5の構成を検証環境に作る | 同じ手順で何度でも作り直せる |
| O7 | 閉域の準備 | 下のチェックリストを1つずつ満たす | チェックリストがすべて埋まる |
| O8 | 閉域シミュレーション | ネットワークを切り、丸1日オフラインで開発・ビルド・起動を行う | 1日を通して作業を完了できる |

## 閉域環境の準備チェックリスト

- [ ] `go mod vendor`で依存を固め、`-mod=vendor`でビルドできる
- [ ] Goモジュールのローカルプロキシ（`GOPROXY=file://...`またはAthens）を用意
- [ ] npmのオフラインキャッシュ、またはVerdaccioでローカルレジストリを用意
- [ ] Dockerイメージを`docker save`で保存し、`docker load`で復元できる
- [ ] Goの公式ドキュメントを`pkgsite`でローカル表示できる
- [ ] PostgreSQL・MDN・TypeScriptのドキュメントのオフラインコピー（DevDocsのオフライン機能など）
- [ ] ローカルLLM（Ollamaなど）とモデルを事前取得し、ネット遮断下で推論できる
- [ ] 上記の手順自体をシェルスクリプトかIaCでコード化している

## 閉域AIデー（任意・O8以降）

AIなしデーとは別に、月1回ほど「閉域AIデー」を設ける。ネットワークを切り、ローカルLLMだけでコード補完とレビューを回し、クラウドAIとの差（精度、速度、扱える文脈の長さ）を記録する。外部にコードを送れない案件でもAIを活用して開発できる、という実績になる。
