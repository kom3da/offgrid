# AIなしデーの運用

AIなしデーは「閉域の現場で1日働く」想定の訓練日。道具を制限し、時間を区切り、必ず記録を残す。

## ルール

- AI補完（Copilot等）とAIチャットはすべてオフ。エディタのAI拡張も無効化する
- 使ってよいもの：`man`、`--help`、`go doc`、`pkgsite`（ローカル）、公式ドキュメントのオフラインコピー、書籍、自分の過去のメモ
- Web検索は1日5回まで。検索したら内容を振り返りメモに記録する
- 詰まったら15分で打ち切り、「詰まりメモ」に書いて次へ進む。翌平日にAIと一緒に解消する
- コードと記録はすべてこのリポジトリにコミットする（コミット規約は README 参照）

## 1日のテンプレート（6時間）

| 時間 | ブロック | 内容 |
| --- | --- | --- |
| 9:00–9:30 | ウォームアップ | 再現ドリル：前回の内容を見ずに再現（下記） |
| 9:30–11:30 | メインドリル | 今のステージのユニット（Stage 1〜2は後半1時間をPostgreSQLに） |
| 11:30–12:00 | 小休止＋メモ | 午前の詰まりを記録 |
| 13:00–14:30 | コードリーディング | 読解課題を1本、図とメモにまとめる（下記） |
| 14:30–15:30 | デバッグドリル | 仕込みバグを3つ直す |
| 15:30–16:00 | 振り返り | テンプレートに沿って記録、次回のユニットを決める |

## ウォームアップ：再現ドリル

前回やった内容を、何も見ずに再現する。Stage 0ではコマンド操作（例：ログから上位10件を出すパイプライン）、Stage 1以降は前回書いた30〜50行の関数。再現できなかった箇所が、今の弱点。

## ステージごとの午後の中身

| ステージ | コードリーディング枠 | デバッグ枠 |
| --- | --- | --- |
| Stage 0 | manページ（`man bash`、`man ls`など）や設定ファイルを読む | 壊れたシェルスクリプト、Gitのコンフリクトを直す |
| Stage 1〜2 | Go標準ライブラリ、小さなOSS | 仕込みバグのGo・TSコードを直す |
| Stage 3〜5 | 中規模OSS、自分がAIで書いた過去のコード | 並行処理・SQL・運用のバグを直す |

## 平日の補助メニュー（30分）

- 月：詰まりメモをAIと一緒に解消し、理解した内容を自分の言葉で書き直す
- 火：AIが書いたコードやコマンドを1つ選び、各行の意味をコメントで書く
- 水：次回のデバッグドリル用に、AIに問題を作らせる（答えは `answers/` に置き、見ない）
- 木：そのステージの読み物（manページ、標準ライブラリ、書籍）を1節読む
- 金：翌日のAIなしデーの準備（ユニットの確認、依存やドキュメントの取得）

## 段階的な導入

最初の3回は午前だけ（3時間）、4〜6回目は午後のコードリーディングまで、7回目からフル6時間にする。
