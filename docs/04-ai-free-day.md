---
title: "AIなしデーの進め方"
---

AIなしデーは「閉域の現場で1日働く」想定の訓練日。道具を制限し、時間を区切り、必ず記録を残す。この1日を、以下では**1セッション**と呼ぶ。進み具合はセッションの数で数え、暦の週には結び付けない。

## ペースを決める

全体の目安は約105〜140セッション。週に何回やるかは自由で、途中で変えてもよい。

- **週1回**：約2年〜2年半。仕事と並行して、無理なく続けられる
- **週2回**：約1年〜1年4か月。間の日が5日あるので、レビューと読書の時間も取れる
- **週3回**：約8〜11か月。間の日が4日しかないので、下の「セッションの間の日」は優先順で削る
- **週4回以上**：勧めない。ウォームアップの再現ドリルは「忘れかけた頃に思い出す」ことで効くので、セッションの間隔が1日だと効き目が落ちる。時間を増やしたいなら、回数ではなく、1回の中の読書と読解の時間を増やす

どのペースでも、1セッションの中身（下の時間割）は変えない。今日が何回目で、何をやるかは、次のコマンドで分かる。

```sh
cd ~/offgrid-log && offgrid
```

AIもネットワークも使わないコマンドで、セッション番号、今日の時間割、開く課題シート、ウォームアップで見返すログを表示する。ほかのサブコマンドは[学習用コマンド](#学習用コマンド)にある。

## ルール

断つのは**答えをくれるもの**だけ。調べること自体は、いくらでもやってよい。

- **AI補完（Copilot等）とAIチャットはすべてオフ。** エディタのAI拡張も無効化する
- **答えのコードがそのまま載っているページも見ない。** Stack Overflow、Qiita、個人のブログ、他人のリポジトリの解答例。AIと同じだけ考える手間を奪うので、AIと同じ扱いにする
- **一次情報は、いつでも好きなだけ見てよい。** `man`、`--help`、`go doc`、`pkgsite`、公式ドキュメント（オンラインでもよい）、ライブラリのソース、書籍、自分の過去のメモ。回数は数えない
- 引いたものは、振り返りの「引いた一次情報」に書く（何を引いて、何が分かったか）
- 詰まったら、下の「詰まったときの手順」に切り替える
- コードと記録はすべてこのリポジトリにコミットする（コミット規約は README 参照）

閉域の現場で効くのは「一次情報を読んで、自分で判断する」力で、ドキュメントが手元にあるかネット越しかは、その訓練に関係しない。だから検索の回数は制限しない。代わりに、答えが書いてあるページを断つ。1日ぶんの作業をネットワークなしで通すのは、それ自体が課題になっている回だけ（O8、C7、下の「閉域AIデー」）。ただし課題の中で、確かめるために短時間だけ切ることはある（O7、C3、C5など。そのつど課題シートに書いてある）。

## 詰まったときの手順

閉域の現場には「翌日のAI」はいない。自力で抜け出す手順そのものを練習する。15分進まなかったら、次の順に試す。

1. エラーメッセージを最後まで読み、分からない単語に印を付ける
2. `man`、`--help`、`go doc`、公式ドキュメントで、その単語を調べる
3. 問題が起きる最小のコードやコマンドを、別ファイルに切り出して再現する
4. 公式ドキュメントを、目次から順に引く（検索語と分かったことを記録する。答えのコードが載っているページは踏まない）

合計45分たっても抜け出せなければ打ち切り、「詰まりメモ」に書いて、同じユニットの別の小課題に進む。詰まりメモは、次のセッションまでの間の日に、AIと一緒に解消する。

## 1セッションの時間割（6時間）

| 時間 | ブロック | 内容 |
| --- | --- | --- |
| 9:00–9:30 | ウォームアップ | 再現ドリルを1本と、前回のレビューで指摘された箇所の直しを1件（下記） |
| 9:30–12:00 | メイン① | 今のステージのユニット。最初の30分は、そのユニットの読書に充ててよい。最後の10分で、午前の詰まりを記録する |
| 13:00–14:00 | メイン② | メイン①の続き。Stage 1〜2は、この1時間をPostgreSQLに充てる。Stage 3は、メイン枠の中でPostgreSQLも扱う |
| 14:00–15:30 | コードリーディング／デバッグドリル | 1回おきに交代する。リーディングは読解課題を1本、デバッグは仕込みバグを3つ |
| 15:30–16:00 | 振り返り | テンプレートに沿って記録、次回のユニットを決める |

新しいことを学ぶ時間（メイン①②）は、Stage 0とStage 3〜5で3.5時間（Stage 3はPostgreSQLを含む）、Stage 1〜2でGo・TSが2.5時間＋PostgreSQLが1時間になる。

## ウォームアップ：再現ドリル

過去にやった内容を、何も見ずに再現する。Stage 0ではコマンド操作（例：ログから上位10件を出すパイプライン）、Stage 1以降は自分が書いた30〜50行の関数。

- 1回に1本だけ。前回の内容と、4回以上前の内容を、1回おきに交互に選ぶ。忘れかけた頃に思い出すほうが、記憶に残りやすい
- 課題シートに「次回のウォームアップでもう一度」とあるものは、その回の1本として扱う
- 30分に収まらない分は、次回に回す。ウォームアップを延ばして、メインの時間を削らない
- 再現率は「元のテストが通ったか」と「途中で何回、元のコードを見たか」で記録する
- 再現できなかった箇所が、今の弱点

## ステージごとの午後の中身

| ステージ | コードリーディング枠 | デバッグ枠 |
| --- | --- | --- |
| Stage 0 | manページ（`man ls`、`man grep`など短いもの）や設定ファイルを読む | 壊れたシェルスクリプト、Gitのコンフリクトを直す |
| Stage 1〜2 | 自分の過去のコード、Go標準ライブラリの短い関数、小さなOSS | 仕込みバグのGo・TSコードを直す |
| Stage 3〜5 | 中規模OSS、自分がAIで書いた過去のコード | 並行処理・SQL・運用のバグを直す。月に1回はTypeScriptのバグも入れる |

## セッションの間の日（1回30分）

AIを使ってよい日。次のセッションまでに、上から順に消化する。時間が足りなければ、下から落とす。

1. **レビュー**：前のセッションの `[no-ai]` コミットのレビューをAIに頼み、指摘を読む（直すのは次のセッションのウォームアップで、自分の手で）。詰まりメモも、AIと一緒に解消する（`prompts/weekly-review.md`）
2. **採点**：`explain.md` を書いたセッションの後は、AIに採点を頼む（`prompts/grade-explain.md`、[評価とステージ通過](06-evaluation.md)）
3. **準備**：次のセッションがデバッグドリルの回なら、AIに問題を作らせる（答えは `answers/` に置き、見ない）。次のユニットの確認と、そのユニットで必要になる取得・インストール（`prompts/next-session.md`）
4. **読書**：次のユニットの「平日に読むもの」の章を読む。週1回のペースなら2日分取れる。取れないときは、セッションのメイン①の最初の30分を読書に充てる

## 段階的な導入

最初の3セッションは12:00まで（3時間）、4〜6回目は14:00まで（4時間）、7回目からフル6時間にする。短縮の回は、ウォームアップ・メイン・振り返りだけにして、最後の30分を振り返りに充てる（PostgreSQLと午後の枠は、7回目から入る）。`offgrid` も、そのとおりに案内する。

## 時間がないときの最小メニュー

ウォームアップとメイン①だけ（9:00–12:00の3時間）でも、1セッションと数えてよい。2週以上空いたときは、新しいユニットに進む前に、再現ドリルを2本やってから再開する。ペースが落ちても、振り返りだけは続ける。

## 学習の1日の持ちもの

セッション中に開くのは、この3つだけ。

1. **学習用コマンド**（`offgrid` か `offgrid serve`）：今やることを出す
2. **エディタ**：コードとメモを書く（[はじめかた](02-getting-started.md)で選んだもの）
3. **本**：そのユニットの「平日に読むもの」の章。手元に無くても進められるが、あると理解が早い

ターミナルは、コマンドを打つために開いておく。ブラウザの画面を使う場合も、**コマンドは自分のターミナルで打つ**（画面の中では打てない）。

## 学習用コマンド

`offgrid` を、引数なしで実行する。今の進み具合と、気になるところ（作業漏れ）を出して、メニューを出す。番号を選べば、あとは案内に従って進められる。

```sh
cd ~/offgrid-log && offgrid
```

**`run`（メニューの1番）が中心。** セッションを上から順に案内する。

1. ウォームアップ（見返すログのパスまで出す）
2. メイン：課題を**1問ずつ**出す。`Enter`＝できた、`s`＝詰まった（メモを書く）、`l`＝あとで、`k`＝手がかり（キーワードと詰まりやすいところを表示）、`d`＝この枠を終える、`q`＝中断
3. PostgreSQL（Stage 1〜2は別枠。Stage 3はメイン枠に合流する。どちらも `PROGRESS.md` の「次のPostgreSQLユニット」を見る）
4. コードリーディング／デバッグドリル（1回おきに交代）
5. 振り返り：空欄を1つずつ聞いて、書き込む
6. 終わりの手続き：残すものの確認、完了の記録、コミット

最初の6回は、上の「段階的な導入」のとおり短い時間割（ウォームアップ・メイン・振り返り）で案内する。7回目から、PostgreSQLと午後の枠が入る。

`q` で中断しても、続きから再開できる。どの枠まで終えたかを覚えているので、ブラウザの画面（`offgrid serve`）と行き来してもよい。課題の進み具合は、ユニットのディレクトリの `work.md`（ツールが作るチェックリスト）に入っている。

ほかのサブコマンド：

- `today`：今日やることの一覧だけを表示する
- `status`：進捗と、**作業漏れの疑い**（課題が全部できているのに未記録、完了なのに残すものが無い、途中のユニット、書いていない振り返りの欄、コミットやpushの漏れ）
- `next [ID]` / `tick <番号>`：次の課題だけ見る／できたことを記録する
- `unit [ID]`：課題シートを読む
- `find <語>`：カリキュラム・課題シート・自分のメモを全文検索する。ネットワークを切っていても引ける
- `check [ID]`：確認コマンド（`shellcheck`、`go vet`、`go test`、`tsc`、`vitest`）を実行し、「残すもの」と完了条件を表示する
- `stuck "<文>"`：詰まりメモを、振り返りの「詰まったこと」に時刻付きで書く
- `timer [分]`：残り時間を計る（既定15分。詰まったときの区切りに使う）
- `retro [ファイル]`：振り返りの空欄を、1つずつ聞いて埋める
- `done [ID]`：完了条件を確かめて、`PROGRESS.md` に記録する
- `end`：終わりの手続き
- `serve`：ブラウザで開く画面を、手元に立てる（下記）
- `selftest`：課題シートが、この版のツールで読めるかを検査する（カリキュラムを取り込んだ直後の確認に使う）
- `version`：いま入っているツールの版を表示する

「どこまでやったか分からない」を防ぐのは `status` と `end`。`PROGRESS.md` の手書きだけでなく、**実際に残っているファイル**と `work.md` のチェックを見て判定する。各課題シートの「残すもの」に書かれたファイルが、その基準になる。

このコマンドは、Go で書かれた1つの実行ファイル（`tools/offgrid` のソース）。Day 0 に入れておけば（[はじめかた](02-getting-started.md)）、あとはネットワークもAIも使わずに動く。新しい版は、カリキュラムと同じタグのリリースに付く。

### ブラウザで使う（`offgrid serve`）

画面を広く使いたいときは、手元に画面を立てられる。

```sh
offgrid serve          # http://localhost:7777
offgrid serve --open   # ブラウザも開く
```

**「いまやること」の画面が主役。** ターミナルの `run` と同じ案内を、ボタンで進められる。

- 上に今日の枠（ウォームアップ／メイン／午後／振り返り／終わり）が並び、**今どこにいるか**が一目で分かる
- 課題は**1問だけ**大きく出る。「できた」「あとで」「手がかり」「この枠を終える」「詰まった」を押して進む
- **時間を見て口を出す。** 同じ課題に15分たつと、手順に切り替えるよう促す。45分で打ち切りを促し、詰まりメモの欄を開く
- ウォームアップでは、**前回の詰まりメモ**を出す（同じところで止まるなら、それが今の弱点）
- 「あとで」に回した課題は、その枠の最後に戻ってくる。終わりの手続きでも、残っていれば知らせる
- 終わりの手続きで、**確認コマンド（`shellcheck`、`go vet`、`go test` など）をその場で走らせて、出力をそのまま見せる**。完了の記録とコミットも、その画面から
- 振り返りは、空いている欄が入力欄として並ぶ。書き込むと、そのままファイルに入る
- 課題シートとカリキュラム（`docs/` 全部）も、この画面で読める。検索もできる
- **画面のコマンドは、クリックでコピーできる。** 打つ場所は自分のターミナル（その注意も画面に出る）
- **メモを、その場で書ける。** 課題の下の「メモを書く」に1行入れると、そのユニットの `notes.md` に時刻付きで入る
- はじめて開いたときは、使い方が3行で出る。あとからでも「使い方」のページで読める
- **外には出さない。** `127.0.0.1` だけで待ち受け、同じマシンからの接続しか受け付けない。ネットワークにもAIにもつながない
- **ほかのページから操作されない。** ボタンを押したときだけ書き込む作りにしてあるので、この画面を立てたまま別のサイトを見ていても、勝手にコミットされたりしない
- **答えのファイル（`answers/`）は、この画面では開けない。** 見るなら自分でエディタから開く（それが自分の判断だと分かるように）
- LimaやWSL2の中で動かしていても、手元のブラウザから `http://localhost:7777` で開ける（ポート転送）
- 画面はバイナリに埋め込んである。閉域でもそのまま動く

進み具合は、ターミナルと同じファイルに入る（`work.md`、`PROGRESS.md`、`logs/`）。その日の枠の進行だけは `logs/<年>/.<月-日>.state.json` に入る。どちらから使っても、続きから進められる。

## 課題シートは、ネットワークがなくても読める

このカリキュラムは[ブラウザでも読める](https://kom3da.github.io/offgrid/)が、セッション中に開くのは、自分のリポジトリの中のファイルでよい。課題シート（`drills/<トラック>/<ユニット>/TASKS.md`）とドキュメント（`docs/`）は、ただのMarkdownなので、エディタでも `less` でも読める。ネットワークを切る回（O8、C7、閉域AIデー）では、これが唯一の読み方になる。
