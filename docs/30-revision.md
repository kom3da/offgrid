title: "改訂の運用"
---

このページは、テンプレート（`kom3da/offgrid`）を管理する人のためのもの。学習者は読まなくてよい。

改訂とは、学習テキストとしての内容（`docs/`、課題シート、`prompts/`、`templates/`、`scripts/`）を直すこと。誰かの学習の進み具合とは関係なく、内容上の理由だけで行う。学習者は、好きなときに `scripts/update-curriculum.sh <版>` で取り込む（[はじめかた](02-getting-started.md)）。

## 版の付け方

版は `MAJOR.MINOR.PATCH`（例：`v1.2.0`）。1つの番号で、カリキュラムと学習用コマンド（`tools/offgrid`）の両方を指す。

- **MAJOR**：課題シートの書式、`PROGRESS.md` の書き方、`work.md` の形など、**ツールとの約束が壊れる**変更。学習者は、取り込みと同時にツールも入れ替える必要がある。`CHANGELOG.md` に、その旨をはっきり書く
- **MINOR**：ユニットや機能の追加、文章の書き直し
- **PATCH**：誤り、動かない手順、表記の修正

タグを push すると、リリースにバイナリが付く（`.github/workflows/release.yml`）。**カリキュラムとツールの版は、いつも同じ番号**になる。変更点は `CHANGELOG.md` に残す。学習の進み具合（ステージの通過やセッションの回数）には、タグを付けない。

## 改訂のきっかけ

| 種類 | きっかけ | 範囲 |
| --- | --- | --- |
| 修正 | 誤り、動かない手順、詰まりやすい箇所の報告があったとき（随時） | 該当箇所だけ |
| 追加 | 未整備の部分を書き足すとき（Stage 1以降の課題シート、各ユニットで読む章、未検証の手順の検証） | 追加する部分だけ |
| 定期点検 | 1年に1回 | 全体（下の「定期点検で確かめること」） |
| 全面改訂 | Goのメジャーな変更、主要ツールの置き換え | 構成から見直す |

報告は、GitHubのIssueで受ける。学習者の `logs/` は個人の記録なので、改訂の材料として読みにいかない。

## 未整備の部分

一覧は、テンプレートの [Issues](https://github.com/kom3da/offgrid/issues) にある（`未検証` と `未整備` のラベル）。**ここには書かない。** `docs/` は取り込みで学習者に配られるので、管理者のやることリストを全員に渡してしまう。

誤りや提案の受け付けも Issues で行う（テンプレートが2つある：誤りの報告／改訂の提案）。学習者から届いたものは、改訂のきっかけとして扱う。

### ラベルの付け方

ラベルには2つの性質がある。**状態のラベルは、状態が変わったら外す。** 外し忘れると、`未検証` で検索したときに、検証が済んだものが混ざる（実際に起きた）。

- **状態**：`未検証`（書いてあるが実機で確かめていない）、`未整備`（欠けていると分かっている）
  - 確かめた／作ったら**外す**。閉じるときも外す（閉じただけでは、検索に残る）
- **種類**：`誤り`、`提案`、`質問`
  - 何として届いたかの記録なので、**そのまま残す**
- **範囲**：`curriculum`、`tool`、`site`、`meta`（コミットのタグと同じ語）
  - **そのまま残す**

閉じるときは、**何をどう確かめたかをコメントに書く**。検証で分かった事実が `docs/` や `CLAUDE.md` の記述を変えるなら、そちらも直してから閉じる（Issue にだけ書いて終わらせない）。

全73ユニットの課題シートは揃っている。新しいユニットを足したときは、`prompts/unit-drill.md` の文面で書き、`drills/<トラック>/<ユニット>/TASKS.md` に置く。学習者は、テンプレートにまだシートがないユニットに着いたとき、同じ文面でつなぎのシート（`TASKS.local.md`）を自分で作れる。

## 定期点検で確かめること

- Go・Node.js・PostgreSQL・Docker・Ubuntuの現行バージョンを確認し、課題の記述（構文、標準ライブラリ、イメージ名）を合わせる
- 書籍の版が更新されていないか、絶版になっていないかを確認する
- 推奨ツール（静的解析、負荷試験、ローカルLLM、グラフライブラリ、Lima）が今も主流かを確認する
- オフライン化の手順（DevDocs、pkgsite）と、[はじめかた](02-getting-started.md)の手順が今も動くかを、実機で試す
- 卒業制作の要件が、教えているユニットだけで実現できるかを見直す
- 変更点を `CHANGELOG.md` に書き、版のタグを付ける（`MAJOR` を上げるときは、ツールの入れ替えが必要な旨も書く）

## 手順

1. `prompts/revision.md` をClaude Codeに渡し、古くなった箇所を洗い出す。現行の状況は、記憶ではなく検索で確認させる
2. 提示された変更案を確認し、採用するものだけ反映する
3. `CHANGELOG.md` に追記し、`[docs]`（AIが書いた変更は `[ai]`）でコミットして、版のタグを付けてpushする
4. 課題シートの書式に触ったときは、`cd tools/offgrid && go test ./... && go run . selftest` を通す（CIでも走る）

## 改訂で気をつけること

- ユニットのID（F1、G12など）は変えない。足すときは末尾に足す。学習者の記録が、IDで参照しているため
- 課題シートのファイル名（`TASKS.md`）と、学習者のファイルの置き場所の決まりは変えない。取り込みスクリプトが、この決まりで学習者のファイルを守っている
- 完了条件を厳しくする変更は、`CHANGELOG.md` に明記する。取り込んだ学習者が、通過済みのユニットをやり直すかどうかを自分で決められるようにする
