# 評価基準とセルフチェック

各ステージの最後に、下のチェックリストの8割以上をAIなしで満たし、実技を通過したら次へ進む。満たせなければ、できなかった項目のユニットに戻る。項目が5つ以下のステージは、8割以上＝全項目になる。

## 到達レベルの定義

| レベル | 状態 |
| --- | --- |
| 1 | ドキュメントを見ながらなら書ける |
| 2 | ドキュメントなしで書ける。エラーを自力で読める |
| 3 | 他人（AI含む）のコードの問題点を指摘し、代案を示せる |
| 4 | 設計判断を理由付きで説明し、他人に教えられる |

卒業時の目標は、Linux・Git・GoとTypeScriptがレベル3、SQLとネットワークがレベル2〜3、閉域運用がレベル2以上。

## 「説明できる」の確かめ方

完了条件やチェックリストの「説明できる」は、自己申告にしない。

1. AIなしデーの中で、何も見ずに、課題ディレクトリの `explain.md` に文章で書く
2. 翌平日（月曜）に、AIに採点を頼む。観点は「正確か」「抜けがないか」「自分の言葉で書けているか」の3つ
3. 誤りや抜けを指摘されたら、次回のウォームアップで、何も見ずに書き直す

AIは誤りの場所を示すだけで、模範解答は書かない（CLAUDE.md の「採点を頼まれたとき」）。

## ステージ通過の実技

チェックリストとは別に、各ステージの最後に1回行う。

1. そのステージで作った課題の中から、AIに1本選んでもらう（自分で選ばない）
2. AIなしデーの中で、時間を計り、何も見ずにゼロから作り直す
3. 元のテストが通れば合格。かかった時間を `PROGRESS.md` のメモに残す

## 定期的な見直し

AIなしデー4回ごとに、4回分の振り返り（`logs/`）を並べて見直す。繰り返し詰まったテーマは、次の4回で優先して扱う。[ロードマップ](01-roadmap.md)の目安回数と実績がずれていたら、目安のほうを直す。ペースが落ちても、振り返りだけは続ける。

## 進捗の記録
