# デバッグドリル・コードリーディング

デバッグとリーディングは全ステージを通じて、1回おきに交代で行う（[1日のテンプレート](02-ai-free-day.md)の14:00〜15:30）。「AIが書いたコードを検証できる力」を直接鍛える部分。Stage 0では、壊れたシェルスクリプトやGitのコンフリクトを題材にし、manページを読む練習をする。下のバグのテーマ一覧と読解課題は、Stage 1から使う。

## デバッグドリルの作り方

平日に [prompts/debug-drill.md](../prompts/debug-drill.md) のプロンプトでAIに問題を作らせる。問題は `drills/debug/<日付>-<テーマ>/`、答えは `answers/<日付>-<テーマ>.md` に置き、AIなしデーまで開かない。Stage 4のO3（障害調査）で使う障害も、同じ方法でAIに仕込ませる。

## Stage 0の題材

| 題材 | 例 |
| --- | --- |
| シェルスクリプト | クォート漏れによる空白入りファイル名の誤動作、`set -e`がない、終了コードの見落とし |
| パイプライン | `sort`せずに`uniq`している、区切り文字の誤り |
| Git | コンフリクト、誤ったコミットの取り消し（`revert`と`reset`の違い） |
| ネットワーク | ポートの競合、名前解決できない、`curl`でのステータスコード誤読 |

## バグのテーマ一覧（Stage 1以降）

| 分類 | Go | TypeScript / SQL |
| --- | --- | --- |
| 並行処理 | データ競合、channelのデッドロック、goroutineリーク | Promiseの未await、競合する状態更新 |
| 境界値 | off-by-one、空スライス、整数オーバーフロー | 配列の空、`0`と`""`のfalsy扱い |
| 時刻 | タイムゾーン、`time.Now()`の比較、単調時計 | `Date`のUTC/ローカル混在 |
| nil・NULL | nilマップへの書き込み、nilインターフェース | `NULL`との比較、`NOT IN`とNULL |
| リソース | `resp.Body`の閉じ忘れ、`defer`のループ内使用 | `useEffect`のクリーンアップ漏れ |
| エラー | エラーの握りつぶし、シャドーイング | `catch`での再throw漏れ |
| SQL | トランザクション外の更新、N+1 | インデックスが効かない条件式 |

ステージに合わない分類（Stage 1での並行処理など）は、そのステージに達するまで使わない。

## 解き方の手順

1. 実行し、症状（落ちるテスト、エラーメッセージ）を記録する
2. 仮説を立ててから、ログ出力や`dlv`（Goのデバッガ）で確認する
3. `go test -race`、`go vet`、`staticcheck`、`shellcheck`の出力を読む
4. 直したら、そのバグを検出するテストを1本追加する
5. 答えと照合し、見落としたバグの種類を振り返りに記録する

## コードリーディング課題（難易度順）

| 順 | 対象 | 読む箇所 | まとめる内容 | 目安 |
| --- | --- | --- | --- | --- |
| 0 | `man ls`、`man grep`など短いもの。慣れたら`man bash`の1節 | 気になる節 | 自分用の要約 | Stage 0 |
| 1 | 自分の過去のコード、Go標準ライブラリ `strings` | `Fields`、`Split`、`Repeat` | 処理の流れと、境界値の扱い | Stage 1 |
| 2 | Go標準ライブラリ `net/http` | `ServeMux`のルーティング | リクエストがハンドラに届くまでの流れ | Stage 2 |
| 3 | `spf13/cobra` | コマンド登録と実行 | CLIの構造 | Stage 2 |
| 4 | `jackc/pgx` | 接続プールとクエリ実行 | コネクション管理の流れ | Stage 3 |
| 5 | `prometheus/client_golang` | カウンタとHTTP公開 | メトリクスの保持と並行安全性 | Stage 3〜4 |
| 6 | `caddyserver/caddy` | モジュール読み込み | プラグイン機構の設計 | Stage 4〜5 |
| 7 | 自分がAIで書いた過去のコード | 任意の1機能 | 設計上の問題点と改善案 | 随時 |

読解のルール：grepとエディタのジャンプ機能だけを使い、処理の流れをシーケンス図か箇条書きにまとめる。メモは `drills/reading/` に置く。
