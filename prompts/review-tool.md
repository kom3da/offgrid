---
title: "学習用コマンドのレビュープロンプト（管理者向け）"
---

`tools/offgrid` を変えたあと、**別のセッション**に渡す。書いた本人には自分の穴が見えない（実際に `offgrid serve` のCSRFの穴を見落とした）。

```text
tools/offgrid を、正しさと安全性の観点でレビューしてください。書いたのは別のセッションの私です。
CLAUDE.md の「学習用コマンド（tools/offgrid）を触るとき」を先に読んでください。

このコマンドは、学習者のファイルを書き換え、git を動かし、serve で HTTP を待ち受けます。
学習の記録を壊すと取り返せないので、課題のコードより厳しく見てください。

1. ビルドして、スクラッチ領域に置いたリポジトリの複製に対して、実際に動かして確かめてください
   （本物のリポジトリは変更しない。answers/ は開かない）
2. 次を順に見てください
   - serve の書き込み・実行の経路：GETで起こせるものはないか。Origin / Sec-Fetch-Site / Host /
     トークンの検証を通らない経路はないか。curl で実際に試すこと
   - /file/ と /retro?file= で、リポジトリの外や answers/ を開けないか
   - 書き込みの失敗を握り潰している箇所（`_ =`）。学習者が「記録できた」と誤解しないか
   - 課題シートや PROGRESS.md の解析：番号が飛ぶ、行が消える、シートが増えるとどうなるか
   - ターミナルとブラウザを同時に使ったときの競合。書き込みは原子的か
   - Go としての質：エラーのラップ、境界値、-race
3. 見つけたものは、重要度（高/中/低）、再現手順、実際に観測した結果を添えて表にしてください
4. 最後に「最優先で直すべき3点」を挙げてください

推測で書かないこと。実際に動かして確かめたものだけを報告してください。
```
