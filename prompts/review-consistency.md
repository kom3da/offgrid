---
title: "ファイル間の矛盾のレビュープロンプト（管理者向け）"
---

ルールや数を変えたあと、**別のセッション**に渡す。片側だけ直して終わることが繰り返し起きている。

`python3 .github/check-docs.py` が機械で拾える分（リンク、引退した言い回し、数）は先に潰しておく。このプロンプトは、その残りを人手で読む依頼。

```text
このリポジトリの、ファイル間の矛盾を洗い出してください。READ ONLY で、answers/ は読まないこと。

直近の変更：<何を変えたか。引退させたルールがあれば、その旧い言い方も書く>

**検査の範囲に drills/ の課題シート73本を必ず含めてください。**
docs/ だけ直してシートを忘れる、という取り残しが実際に起きています。

見てほしいもの：
1. 変えたルールの古い言い方が残っているファイル（docs/ prompts/ templates/ README CLAUDE.md
   と、課題シート73本すべて）
2. ツールと文書の食い違い：tools/offgrid のコードが実際にすることと、docs が「こうする」と
   書いていることの差。docs の主張を1つずつコードで確かめる
3. 数の食い違い：ユニット数、ステージごとの目安回数、時間割の合計、トラックの範囲
4. prompts/ と CLAUDE.md の規定の差（課題数、本題の付け方など）
5. サイト（site/）が参照していて存在しないファイル、逆に到達できない docs

**見つけたら、その場で findings.md に1件ずつ追記してから、次のファイルへ進んでください。**
最後にまとめて書こうとしないこと（途中で打ち切られると、それまでの分が全部消えます）。
1件の形式：重要度（高/中/低）／ファイル:行／何が矛盾しているか（該当文を引用）／直し方。
自分で読んで確かめたものだけを報告してください。
```
