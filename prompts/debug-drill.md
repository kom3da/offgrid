# デバッグドリル生成プロンプト

平日（AIありの日）に、下記をAIに渡して問題を作らせる。テーマは `docs/09-debug-and-reading.md` の表から、今のステージに合うものを選ぶ。

```text
以下のテーマで、今の私のレベル（<ステージ名と、学習済みのユニット>）に合わせて、Go（または シェル / TypeScript / SQL）の60〜120行程度のプログラムとテストを作ってください。
未学習の文法や機能は使わないでください。
気づきにくいバグを3つ仕込み、テストのうち少なくとも1つは通るようにしてください。
問題ファイルにはバグの存在を示すコメントやヒントを一切書かないでください。
バグの答えと解説は別ファイル ANSWER.md に分けて書いてください。
テーマ：<テーマ>
```

## Stage 0用の文面

Stage 0では、プログラムではなく、壊れた状態そのものを作らせる。テーマは `docs/09-debug-and-reading.md` の「Stage 0の題材」から選ぶ。

```text
以下のテーマで、今の私のレベル（Stage 0。学習済みのユニット：<F1〜Fn>）に合わせて、デバッグドリルを作ってください。
- シェルスクリプトやパイプラインの場合：20〜40行のスクリプトと、期待する出力を書いたファイルを用意し、気づきにくいバグを3つ仕込むこと
- Gitの場合：壊れた状態（コンフリクトの途中、誤ったコミットなど）の練習用リポジトリを作るセットアップ用スクリプトを用意し、「直したあとの、あるべき状態」を問題文に書くこと
- ネットワークの場合：症状（つながらない、名前が引けないなど）を再現するセットアップ用スクリプトを用意すること。sudoが必要な操作は、問題文に明記すること
未学習のコマンドは使わないでください。問題ファイルに、ヒントや答えを書かないでください。
答えと解説は、別ファイルに分けてください。
テーマ：<テーマ>
```

## 配置ルール

- 問題：`drills/debug/YYYY-MM-DD-<テーマ>/`
- 答え：`answers/YYYY-MM-DD-<テーマ>.md`（AIなしデーの答え合わせまで開かない）。チャットのAIが出した `ANSWER.md` は、中身を読まずにこの名前に変えて移す

Claude Code で生成する場合は「問題は drills/debug に、答えは answers に書き、答えの内容をチャットに表示しないこと」と指示する。
